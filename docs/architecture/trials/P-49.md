# P-49

Batch: none

## Question

What does GraphQL `resolvedBy` say when an App resolves a review thread, read as the App and as a person; and does a thread keep its replies when its first comment is deleted, and what is its first comment then?

## Pass

Each is recorded, so the threads port (§3.3) reads them as GitHub gives them. **Recorded** on 2026-10-23 (`trials/P-49.json`), in the canary, by the trial-author App's installation token at the Maintainer's terminal, and read again by the port's own query on 2026-10-26, the pull request closed. `resolvedBy` is not null: read as the App and as the Maintainer it names `combsmith-sf-trial-author[bot]`, its type the schema's `User`, which says nothing of who resolved it; the port's read gives it the database id the App's comments carry, whose author is a `Bot`. The port reads every resolver as a User, finds no User of that login, and refuses the whole threads read: a pull request whose Lens resolved its own thread is never read whole until #331 types the resolver by its account (P-53). The thread whose first comment was deleted keeps its reply, now its first comment and a reply to nothing, so the port's refusal of a first comment that replies does not fire; the port reads the thread's opener and time from the reply, 2 seconds after the thread was opened. Decision 0069 holds such a thread to the Lens's own record: a thread its Lens recorded must still be opened by that Lens, or the threads read is unreadable
