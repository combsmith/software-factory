# P-60

Batch: none

## Question

Does GitHub serve a commit's tarball as one redirect from api.github.com to codeload.github.com, which answers it with no Authorization header, and does codeload redirect again?

## Pass

One redirect, so the transport may follow it to codeload alone and refuse any second (the Maintainer's "Tarball, allow codeload", 2026-11-04). **Passed** on 2026-11-04 (`trials/P-60.json`), on the canary, asked with no credential: the API answered 302 to `https://codeload.github.com/<owner>/<repo>/legacy.tar.gz/<sha>`, with no token in it, and codeload answered that with no Authorization header 200, a gzip with no `content-length`, whose tar opens with a pax global header naming the whole commit and holds one folder of directories and regular files. No address on codeload over HTTPS redirected; over plain HTTP it answered 301 to the same address over HTTPS. For a commit the canary does not hold the API still answered 302, and codeload 404. What codeload's Location holds for a private repo, read with an App's token, is not asked: it is owed before a live Run reads a private head. The same commit's tree, `GET /repos/<owner>/<repo>/git/trees/<sha>?recursive=1` asked with no credential on 2026-11-05 (`trials/P-60.tree.json`), answered 200 and not truncated, listing every folder and file with its mode, and each file with its size and a blob hash that matched the tarball's bytes, all 22; a commit the canary does not hold answered 422. The review's head is held to that tree (decision 0142)
