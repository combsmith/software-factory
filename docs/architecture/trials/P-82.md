## Question

When a workflow run uploads one small file as the artifact `advice-cost`, with `actions/upload-artifact` at the version the Factory pins, and is then re-run, what does the run's artifact list that `adapters/artifacts.py` reads, `GET /repos/{repo}/actions/runs/{run_id}/artifacts`, answer: after the first attempt; after a re-run of the whole run, whose one job uploads under the same name again; and after a re-run of the failed jobs alone, both of a one-job run that failed after its upload and of a two-job run whose uploading job passed while the other failed? How many artifacts named `advice-cost` does each list hold, with what ids, `created_at` and `expired`, which attempt's file is in each one's zip, and does the second upload under the name succeed? (the Solution Architect, 2026-11-28: a re-run asks no reader and leaves a cost of nought)

## Pass

After the re-run of the whole run, and after the re-run of the one-job run's failed job, the list is 200 and holds exactly one artifact named `advice-cost`, not expired, whose zip holds one file that names the latest attempt, and that attempt's upload under the name succeeded; otherwise a re-run's cost of nought never reaches the pass, which reads two artifacts of the name, or another attempt's file, as a cost it does not hold and counts the worst case (`adapters/artifacts.py`), so the port must instead read the file whose attempt is the record's, a change to the port.
