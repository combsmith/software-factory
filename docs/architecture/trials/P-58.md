# P-58

Batch: none

## Question

Does a pull request's `lastEditedAt` move when its description is edited, and not when only its title is, or when its head is pushed; and does an edit by a bot or an App move it?

## Pass

It moves on a description edit alone, so an enqueue can be held when the description changed after the approval (issue 519). **Passed** on 2026-11-03 (`trials/P-58.json`), in the canary: a title-only edit and a push moved neither `lastEditedAt` nor `userContentEdits`; the Maintainer's description edit moved both, and so did a workflow's bot's, `github-actions`, and the cubic App's own, 23 seconds after the pull request opened. CodeRabbit's summary was an edit too, seen in `userContentEdits` alone, no read falling before the next. `editor` names only the last edit, and `userContentEdits` each, with its `editedAt`; the entry for the opening text takes its `createdAt` from the first later edit. An editor's kind does not make an edit safe: an App's summary is written from the pull request's own text. The reader App's leg **passed** on 2026-11-04 (`trials/P-58.reader.json`): its token narrowed to `pull_requests: read` reads these the same, each editor with its type, login and `databaseId`. On the public canary, `metadata: read` alone was answered the same, so neither grant is shown to be what reads them on a private repo: that case stays open until a private Consumer repo exists (slice 3), as P-56's does. The deleted revision's leg **passed** on 2026-11-10 (`trials/P-58.deleted.json`, issue 549): a revision a person deleted from the description's history is still listed, with its `editedAt` and editor as before and a `deletedAt`, and the deletion moved neither `lastEditedAt`, `editor` nor the count, so the port is answered a deleted middle revision's time as before, and that deletion moved no time. The revision deleted was a middle one, with two later edits above it, so the port's time could not have moved back whatever GitHub did. The Maintainer reported that the browser offered no deletion of the newest revision, which no exchange shows; whether anything else deletes one, and what GitHub answers then, was not asked
