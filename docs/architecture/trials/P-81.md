# P-81

Batch: 4

## Question

When a pull request review is started, left pending while the pull request gets an issue comment, and submitted more than a minute later, where does the issue timeline that `adapters/seen.py` reads from its end, `GET /repos/{repo}/issues/{n}/timeline`, put the `reviewed` event: by when the review was submitted, or by when it was started? What `submitted_at` does it carry, and what does the reviews list, `GET /repos/{repo}/pulls/{n}/reviews`, show of the review? (issue 1219)

## Pass

On every read after the submission, at `per_page=100` and page by page at `per_page=2`, the `reviewed` event comes after the issue comment made while the review was pending, and on every read after the later comment it also comes before that comment; its `submitted_at` is no earlier than the pending comment's `created_at` and no later than the later comment's, both by GitHub's clock; and each read's moments, as `adapters.seen._moments` reads them, run in time order, so that the last `per_page=2` pages replayed through `adapters.seen._tail`, from a `since` before the first act, read whole. A read made before GitHub shows the review submitted is recorded, deciding nothing. A fail opens an issue against the design before issue 1219 closes: a replay read short means `_tail` reads every pull request with such a review as short, for good (the limit pull request 1217 states); a `submitted_at` before the pending comment means `adapters/seen.py` passes over a review started before `since` and submitted after it; a placement alone that fails is recorded beside the replay's verdict. Recorded, deciding nothing: what the timeline and the reviews list show while the review is pending; the review's state and `submitted_at` in the reviews list, whose order one review cannot show; and the line comment the review holds, whether the timeline names it, and its `created_at`, the moment it was drafted or the moment it was submitted. Limit: one App, the pr-review App, makes every write and every read, so the reads while the review is pending are its author's own; a submitted review is public, so the reads the pass rests on are the same for any reader, the Controller among them.
