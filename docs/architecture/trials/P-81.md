# P-81

Batch: 4

## Question

When a pull request review is started, left pending while the pull request gets an issue comment, and submitted more than a minute later, where does the issue timeline that `adapters/seen.py` reads from its end, `GET /repos/{repo}/issues/{n}/timeline`, put the `reviewed` event: by when the review was submitted, or by when it was started? What `submitted_at` does it carry, and where does the reviews list, `GET /repos/{repo}/pulls/{n}/reviews`, put the review? (issue 1219)

## Pass

On every read after the submission, at `per_page=100` and page by page at `per_page=2`, the `reviewed` event comes after the issue comment made while the review was pending and before the one made after it was submitted; its `submitted_at` is no earlier than the pending comment's `created_at` and no later than the later comment's, both by GitHub's clock; and each read's moments, as `adapters.seen._moments` reads them, run in time order, so that the `per_page=2` pages replayed through `adapters.seen._tail`, from a `since` before the first act, read whole. Otherwise `_tail` reads every pull request that holds such a review as short, for good (the limit pull request 1217 states), and the order check must follow what GitHub does before issue 1219 closes. Recorded, deciding nothing: what the timeline and the reviews list show while the review is pending; the reviews list's order; and the line comment the review holds, whether the timeline names it, and its `created_at`, the moment it was drafted or the moment it was submitted. Limit: one App, the pr-review App, makes every write and every read, so the reads while the review is pending are its author's own; a submitted review is public, so the reads the pass rests on are the same for any reader, the Controller among them.
