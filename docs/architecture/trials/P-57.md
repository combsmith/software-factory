# P-57

Batch: none

## Question

Does the merge queue refuse an enqueue whose `expectedHeadOid` is not the pull request's head, and accept one whose is, as the queue step asks it?

## Pass

Yes: the queue step names the head the Kernel admitted, so a push between the admission and the enqueue makes the enqueue fail and nothing enters the queue (issue 381). A push while the pull request is queued is not asked here: an App's push through the contents API was refused then, 409 (`trials/P-2.queue.json`), and a git push is not recorded. **Passed** on 2026-11-03 (`trials/P-57.json`), in the canary, through the Maintainer's login, the ruleset's approval set aside for the trial and restored: an enqueue naming the head before a push was refused, "Failed to add PR #93: expected head oid does not match the current head oid", with no queue entry, and one naming the current head was queued, then dequeued. GitHub checks the head before the review: unapproved, the stale enqueue was refused for its head and the current one for the code owner's review.
