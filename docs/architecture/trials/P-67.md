# P-67

Batch: 4

## Question

When the merge queue squash-merges a pull request whose description closes an issue, does GitHub close the issue, and does the issue's timeline name the pull request as the close's closer, or the squash commit, or neither? How long after the merge is the close recorded?

## Pass

The issue is closed, its closer the pull request or its squash commit, within `max_close_lag_seconds` of the merge, so the port reads a queue's squash as it reads P-33's merge (§4.1, issue 821). **Passed** on 2026-11-13 (`trials/P-67.json`), riding on P-66: the queue's squash merges of canary pull requests 116 and 114 closed issues 119 and 118, each `closedAt` 2 s after its merge and its closed event timed 3 s after. Each `ClosedEvent` names the pull request its `closer`, a `PullRequest` with the squash commit as its `mergeCommit`, never a `Commit`, and the Maintainer, who enqueued it, its actor; REST's `closed` event gives `commit_id` null and names no closer; `closedByPullRequestsReferences` gives each issue its one pull request, merged
