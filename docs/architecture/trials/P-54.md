## Question

Can the Controller's installation token, narrowed to `issues: read` on the canary alone, read the issue a pull request is bound to, `GET /repos/{repo}/issues/{n}`, as the acceptance port's `labelled()` reads it; and what is a token narrowed to `metadata: read` alone answered for the same read? (issue 342)

## Pass

The narrowed token is answered 200 with the issue: its number, no `pull_request`, and labels each with a name; otherwise the acceptance port cannot read a bound issue's labels under the Controller's grant. **Passed** on 2026-10-30 (`trials/P-54.json`): 200 with the issue, and GitHub's `x-accepted-github-permissions` says `issues=read`. Recorded, deciding nothing: the `metadata: read` token is answered 200 too, since the canary is public (decision 0068).
