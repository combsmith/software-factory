# P-62

Batch: none

## Question

Does the contents API, asked with the raw media type, answer a file of more than 1 MiB with its bytes whole, in one answer and no redirect; and does the git blobs API answer the same blob as base64?

## Pass

Whole, in one answer, so that the eval job reads a case's head and tree from the held-out home with the home's token alone ("A case's head is read from the private home, pinned by its hash, and the run is sharded", issue 611; the Factory Builder's ruling of 2026-11-08, (d)); the git blobs API is the fallback. **Passed** on 2026-11-09 (`trials/P-62.json`), by the Factory Builder's ruling of 2026-11-08 that "the raw media type" in its pass condition is answered by `application/vnd.github.raw`, the type the transport must ask for, and that `gh`'s failure on `application/vnd.github.raw+json` with the Maintainer's login is a fault of the client on a type the Factory will not use, not GitHub's answer; in the canary, on a file of 1,577,185 random bytes on a branch made for it and deleted after: asked with `application/vnd.github.raw+json` with no credential, or with `application/vnd.github.raw` with the Maintainer's login or none, the API answered 200 with a `content-length` of the file's and the file's bytes exactly, by their sha256, and no redirect. Asked as JSON it answered the file's size with `content` empty and `encoding` `none`. The git blobs API answered the blob as base64 that decoded to the same bytes, and with the raw media type as `application/octet-stream`. With the login, `application/vnd.github.raw+json` was answered 200 with a `content-length` of the file's, but `gh api` wrote no body, saying "transform: short source buffer", three times; and the transport reads any answer whose type ends in json as JSON, so every reader, the transport among them, asks for `application/vnd.github.raw`, whose answer's type does not. What the API answers for a private repo's file is not asked here. Should it answer the held-out home's otherwise, a redirect among them, the read fails closed: the transport follows no redirect for a file, and a head not read whole is `head_unreadable`
