## Question

Can the Controller's installation token, narrowed to `pull_requests: read` on the canary alone, read a pull request's comments, `GET /repos/{repo}/issues/{n}/comments`, as the seen port reads them; and what is a token, narrowed to `metadata: read` alone, answered for the same read? (decision 0061)

## Pass

The narrowed token is answered 200 with the comments, each with an id and a user with an id and a type, and GitHub's `x-accepted-github-permissions` names `pull_requests=read`; otherwise the need moves to what it names. **Passed** on 2026-11-01 (`trials/P-56.json`): 200 with five comments, and the header says `issues=read; pull_requests=read`. Recorded, deciding nothing: the `metadata: read` token is answered 200 too, since the canary is public (decision 0068).
