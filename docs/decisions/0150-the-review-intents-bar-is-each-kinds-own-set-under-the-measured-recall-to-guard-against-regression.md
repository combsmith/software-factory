# 0150. The review Intent's bar is each kind's own, set under the measured recall to guard against regression

Status: accepted. Replaces `docs/decisions/0120-the-gate-holds-a-bar-of-the-set-and-of-each-kind-and-a-fault-of-the-engine-or-the-run-still-closes-it.md`, and keeps all of it but two rows, "The bar" and "A blocking case", which it overturns, and four that name them, "Where it is computed", "What the run says", "What the bar does not hold" and "The eval gate", which it restates below. The Maintainer's ruling, restated to this lane by the Factory Builder on 2026-11-06: re-baseline the eval bar for v0.1.0, the first Release. What closes the gate whatever the bar, the split, the report and its words stand as 0120 decided them.

## Decision

| What | Decided | Because |
|---|---|---|
| The bar | Each kind is held to its own bar: at least 90% of the clean cases, those that expect a criterion met, and at least 30% of the cases that expect a Finding. They are `BAR_OF_A_KIND` in `harness/eval/__init__.py`, one table that `kinds_pass` reads in the job, where the cases are. Each is a whole fraction compared by multiplying, so a share exactly on the bar clears it | The Maintainer's ruling. Whole numbers, so that no rounding decides a boundary |
| What it is | A guard against regression, not the measure of a sound reviewer. It is set under the measured recall, so that the noise between runs cannot close it alone | In two private runs of the set, at medium and at high effort, recall on the cases that expect a Finding was about 40–45%, and the runs differed by about 2–3 cases. A bar at the measure would close on noise |
| What goes | 0120's bar of the whole set and of each kind. And the rule that every case that expects a blocking Finding must pass, whatever the bar | In both runs the model missed a case that expects a blocking Finding. A rule that no run of today's reviewer clears closes the gate to every Release and guards nothing |
| The blocking word | `blocking_pass` stays in the report, computed as before, and the judge's line still says "a blocking case not passed". It closes nothing by itself. A set still holds one such case, `BLOCKING_LEAST`, or `split_ok` is false | The recall work must show that miss going away, so it stays in sight. What 0120 accepted of the word, that it can tell which ids expect a blocking Finding, is unchanged |
| The set's share | `verdict` holds the report's passed cases to the fewest a set could have passed with each kind on its bar, `least_passed`, derived from `BAR_OF_A_KIND` and no number of its own. Where the report says the split held, each kind holds `KIND_LEAST` cases, so the fewest are 90% of those clean ones and 30% of every other case: 24 of 40. Where it does not, it is 30% of the whole set, and the run is short all the same. A report that says each kind cleared, with fewer passed, is `case_failed`. A report the job wrote always clears it | The verdict takes each kind's word from the job. Without a bar of the set, nothing else would hold that word to the report's own cases, and the Release's gate reads a report it downloads by `verdict` too |
| Where it is computed | Each kind's word in the job, where the cases are, as `kinds_pass` against its own bar: one word for each kind, never how many, null where a case was not read or its answer is no kind. The set's share in `verdict`, from the report's own cases, as the row above says. `verdict` and the judge use both, and the Release's gate reads them by `verdict` | 0120's row, but for the bar of the set |
| What the run says | `case_failed` names a run with a kind under its bar, or with fewer passed than its words allow. The judge prints its one line on `engine_fault`, `run_fault` and `case_failed`, and on a run that passes, so that the cases not passed still show; the line names each kind under its bar, and says "a blocking case not passed" whether the run passes or not | A green run with cases not passed must say so, a missed blocking case most of all |
| The eval gate | `next` moves only to a commit whose eval report clears each kind's bar of a non-empty set, judged for that Release. It is read before the tag is created, so a closed gate burns no version | 0120's row, but for the bar |
| What a pass needs | A set of at least one case, every case the manifest names once by its id and hash, no fault of the Engine or the run, `split_ok` true, and each kind's bar cleared. Everything else `verdict` checked before, it checks still | 0120's checks, but for its bar |
| How it rises | The bar rises as the measured recall rises, each time in a record of its own that names the runs that measured it. Work on recall comes in stories of its own | A guard that is never raised stops measuring anything |
| What the bar does not hold | No floor by criterion or by severity, `blocking` now among them. A reviewer that raises nothing clears the clean cases and fails the 30%. One that raises a Finding on everything fails the 90%. A reviewer that finds one fault in three clears it. A commit under the bar may be dispatched again, as the gate takes the newest run that succeeded, and the model varies, so a run near the bar may clear on a later try: only the Maintainer dispatches, and that is the Maintainer's to weigh | Said so that a green gate is not read as more than it holds |
| Where it sits | In `harness/eval/__init__.py`, where 0120's numbers sat. `tools/hooks/protected.py` does not hold that file yet, as 0120 said; decision 0117's rule, that what grades the review needs a person, still waits on its story | Unchanged from 0120 |
| What is public | This record, the code and the tests give no count and no id of the held-out set. The measures above appear only as rounded ranges | The held-out rule: nothing of the set but its manifest is here |

## Why

0120's bar was set before any run read a case with its issue, so that it could not be fitted to the results. The runs since have measured the reviewer, and today's reviewer cannot clear it. A gate that stays shut gives no signal, and it blocks the first Release. Set under what was measured, the bar still closes on a reviewer that gets worse, which is the regression a Release must not ship, and does not close on noise. Recall is raised in stories of its own, and the bar follows it up.
