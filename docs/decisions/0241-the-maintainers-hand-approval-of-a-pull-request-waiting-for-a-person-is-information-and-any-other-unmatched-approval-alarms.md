# 0241. The Maintainer's hand approval of a pull request waiting for a person is information, and any other unmatched approval alarms

Status: accepted. The Solution Architect's ruling of 2026-11-20 on "Reconciliation reads the Maintainer's hand approval of a hand PR as an approver write nobody matched" (issue 1026), as the Factory Builder relayed it. It amends 0198's row "What follows a hand approval", where it says that the reconciliation raises `write_unmatched` for every hand approval; the rest of that row, and of 0198 and 0061, stands.

## Decision

| What | Decided | Because |
|---|---|---|
| The gap | Every machine-user approval no Effect records raises `write_unmatched` (0061), the Maintainer's hand approvals included (0198), so while hand pull requests flow the alert never clears, and it hides the entry it exists for | On 2026-11-20 it named seven approvals, each his own |
| A hand approval | A machine-user approval no Effect records, where the last pass record before it decided its pull request with `model_lens_input_needs_person` or `path_needs_person` at the very commit it approved, the first approval of that head. It is the information entry `hand_approval`, beside `merged_by_override`, naming the pull request and the review, and raises no alert | The Kernel gives those codes alone to a change only a person may approve, which the Factory never approves: a model Lens's input (0052), and a path only a person decides, named for itself by 0207. The ruling's reference to 0200 meant 0207's code, `path_needs_person` |
| Still `write_unmatched` | An approval under any other code; a second approval of a head, the first matched, unmatched, keyless or a Role's; two approvals of a head in the same second, or where one's time cannot be read; any approval while a read is short, of what was seen, of what was recorded or, once the pass job's token is an identity, of the Runs; one of a head or pull request that pass did not decide, or with no record before it at hand, or with one at hand whose time cannot be read; one whose commit, time or key cannot be read; and so the cannot-review hand merge under a Pause | Only what the Factory recorded lets an approval through; what it cannot read is never information |
| The commit | `seen/1` carries each approval's commit, the review's `commit_id`, only where its state reads as approved, a dismissed one's by its state before; null otherwise. Never matched by its pull request alone | A head moves, and what cannot be read is never information |
| Carried | Each hand approval is carried in `reconciled.hand`, by key, pull request, head and time, and each head any other approval took, matched, unmatched, keyless or a Role's, in `reconciled.taken`, while its pull request is open or its `left` entry is still held, and dropped by the pass that drops that entry, by the same window, one clock. An approval read on a pull request that reads as left, given and merged between two passes, is judged and carried as any other; a reopened pull request keeps its entries. | A pass holds the last two records, and an approval leaves the window after 30 hours while its pull request may wait longer; and a pull request that left is read until the window passes its leaving, so carrying less would read each merged hand pull request's approval as unmatched for up to 30 hours |
| Until the next part | No pass writes either list into its record until the next part of this change, so a record holds neither and a head is taken within the window alone; reconciliation already reads both from the record before | The carry and its record are that part's |
| A limit | GitHub lets an approver name the commit an approval is of, an older one among them. Such an approval is information only where the last pass before it decided the pull request at that older commit, which a later push has since left; it approves nothing GitHub counts for the newer head | GitHub's reviews API takes a `commit_id` |
| A rollback | A Release cut before this one refuses a pass record that holds `reconciled.hand`, `reconciled.taken` or a `hand_approval` entry as no `pass/1`, until the last two records hold none, as 0201 accepted for `outcome/1` | Pass records are read by every later pass |
| From the cut, and after an outage | A head approved before the first Release that carries `taken`, or before a gap in passes longer than the window, and out of the window by then, is unknown to it, so an approval of that head after the cut can read as the first. Bounded by the hand pull requests open at the cut, each of whose entries the Maintainer reads | The records before hold no history to read |
| The schemas | `seen/1` takes a commit on any write and `view-meta` a `hand_approval` entry of any shape: `controller/reconcile.py` and `adapters/seen.py`, the one writer of each, hold the shape, by the tests below | The schema reader takes no conditional shape |
| The residual | A stolen machine-user token used on a real hand pull request at the head its pass read reads as information. What stands against it: the Maintainer reads every `hand_approval` entry and matches it to an approval he gave, one he did not give asking for the token's rotation; and someone must still enqueue | Accepted by the Solution Architect's ruling |

## Why

The alert was for a use of the login that is not the Maintainer's. The one approval the Factory can tell from what it recorded, of a head the Kernel held for a person, is let through as information; every other still alarms, and each entry is still read.
