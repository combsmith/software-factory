# 0174. The writes check reads a name where it is stored, every class and owner it may be, and exec as its own only where a binding always runs

Status: accepted. The Factory Builder's story of 2026-11-09, issue 655, "check_writes: routes still open after issue 640, an aliased stored name, a second class traced, exec by a binding that never runs", with the four routes Muse's read of the merged pull request "Check_writes holds a class by any name, another module's names, sys reached other ways, code run from text and a command a shell runs" added to it. It amends decision 0171's row "Still not held".

## Decision

| What | Decided | Because |
|---|---|---|
| A name read where it is stored | `tools/check_writes.py` reads a name stored under an `if`, a `try` or a walrus, and a name a function declares `global`, back to the module whose own code stores it, through each import and re-export of it, `from a import P as Q` (`_origin`). What that module stores it as, and what each of its functions that declares it `global` assigns it, is read, as decision 0171 reads them in the module that names it | `_traced` looked the name up as the importer spells it, and read only the current module's `global` assignments |
| Every class and owner it may be | An attribute set on a name that may be more than one class is refused if any of them is outside its module's top level. An attribute or a key set on a name that may be more than one module's value is given apart for each owner, so PATCHERS allows each only by name | Decision 0171 read the first class and the first owner alone, so a second one was let through, a PATCHERS file's among them |
| Another module's names held first | `vars(m)` or `m.__dict__` held by a name, a function's or the module's own, and then handed to a call, is refused as when it is handed on at once (`_namespaces`). An unbound fill, `dict.update(other.TABLE, ...)`, `list.append`, `set.add` and their kind, fills its first argument, and is read as the bound one is | Decision 0171 refused only the expression handed on in place, and only the bound fill |
| A nonlocal value two steps away | What a nested function assigns a name it declares `nonlocal` is read in that function's own scope, so a local name it gives first, `p = Port; c = p`, is followed | It was read in the outer function, where `p` is no name |
| exec, eval and compile, as a module's own | Only an import or a definition at the module's top level, under no `if`, `try` or function, exempts the name, and not if it is deleted anywhere, `del exec`, or bound two ways | A binding that may never run, or that is undone, leaves the builtin |
| Loads reached other ways | A loader module's name, `sys`, `modules`, `__builtins__` or `__import__` given as a literal key, `getattr` argument or `get` argument, and `__builtins__` as any module's attribute, is a load by name | `getattr(mutants, 'importlib')`, `k.__builtins__['eval']` and `vars(os).get('sys')` each reach a module by its name |
| Shell words | A command after a `case` pattern's `)`, after `eval`, `watch` or `stdbuf` with their options, and after `timeout` with options that take a value, `timeout -s KILL 60 git push`, is a command | Each runs the next word |
| One module, two files | Two files that are one module, a module's own file and a package's file of the same dotted name, are refused, and a function's reading is cached under its node, never its id | Which one Python imports cannot be told, and the run dropped the second while its cache entries stayed, keyed on ids a later tree could reuse |
| Still not held | As decision 0171 names, but for the routes above: a RUNNERS function handed a write's arguments by its caller; a name given by a loop, a `with`, a container, a call's return or a starred part; a module reached by `getattr` of a name that is not a literal, by `unittest.mock.patch`, or another Python run as a process; a command after a backtick, built from parts, or read from outside the code; a `match` capture's shadow | Each is still the review's, for the reasons decision 0171 gives |

## Why

The reads of issue 640, "check_writes: routes still open after issue 596, a runner's helper, a class or instance reached through another name, sys.modules by getattr", and of the pull request that closed it found these routes after their changes' last fix rounds. Each is a pattern the syntax names, taken only by code written to hide a write, so the check names it. None is on main, which passes as before.
