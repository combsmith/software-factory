# NNNN. A private replay may switch on four review approaches, each off in the committed configuration

Status: accepted. The Factory Builder's rulings of 2026-11-10 on issue 581, "The review Role's recall on planted faults": the design of lane d, its merge rule, one replay of each approach first, and one pull request of switches, all off. Each approach the issue names is to be measured by a private replay at the Maintainer's terminal against the same commit without it. This record makes each one switchable in a replay's own copy of the configuration, and changes nothing a live Run or the gate is asked.

## Decision

| What | Decided | Because |
|---|---|---|
| The switch | `config/harness.json` may give a `review` block: `passes` (`whole` or `per_file`), `runs` (1 to 3), `checklist` and `read_head` (true or false). The committed file gives none, and none is the defaults: one pass, once, told what a review is always told. A block with any other key or value is refused before anything is asked, never read as something else | A replay copies the repo at a commit and changes its own copy of this file, as it already does for effort and limits, so one command measures one approach against the same commit |
| Where it acts | `harness/run.py`'s `answer`, the one function that answers both a live Run and a held-out case, reads the block for a reviewing Intent alone. Every call it makes is the call it always made, through `engine.run`; each call after the first is a session of its own | So a replay measures exactly what a live Run would do with the switch on |
| A pass per changed file | `per_file` asks one Task per changed file, the diff cut at each file's header and the head left whole, and joins the answers. A change of one file, or of more than eight, is asked whole | A fault in a file read late is not crowded out; the bound keeps a replay's cost per case in sight |
| Union across runs | `runs` asks the whole Task that many times and joins the answers. The cost bound is three runs, each held to its tier's ceiling | A true union, as ruled: what it costs on the clean cases is what the replay is to measure |
| A fault checklist | `checklist` tells the review, after its rubric, the fault kinds each criterion covers, from `roles/pr-review/checklist.json`, and asks it to weigh each before it judges a criterion met. The file holds to `checklist/1`, is among the Role's own files and so a model Lens's input, and is written from the rubric and the design alone, never from a replay's output or a case. A checklist that cannot be read is `rubric_unreadable` | The rubric and its digest stay as they are, so the gate's identity of the review is unchanged |
| Reading the head first | `read_head` tells the review, after the head's note, to read each changed file at the head around each hunk before it judges a criterion met. Nothing can enforce the reads; the replay measures whether the words move recall | The head is already readable (decision 0138) |
| The merge rule | Findings on the same path with lines that overlap are one, whatever each cites; the one most of the answers agree on by criterion, severity and category is kept, the earliest on a tie. A Finding elsewhere, or with no lines, is kept whole. Each kept Finding is posted once, as its own answer posted it, renumbered. A criterion is a finding where any answer found it; met where one judged it met and every other met or not applicable; otherwise as the first that covers it says. Usage is summed, none where any call counted none. The joined Result is completed only if every call completed, and is otherwise the first that did not, by its own reason; one that does not hold to its schema is `result_invalid` | Decision 0160 fails a case with two Findings at its place, so a union that kept both would score a fault found twice as worse than found once. A pass of one file rightly calls a criterion of another file not applicable, and that must not hide the pass that judged it met |
| What is unchanged | The committed configuration, every live Run, the gate, the rubric, the Role's prompt and the eval report's identity of the review. An approach is kept only by its own pull request, which turns it on in `config/harness.json` and ships with a full replay at its head, as the issue asks | Measuring is not deciding |

## Why

The issue names four ways the review might find more of the faults planted in its cases, and asks that each be measured against the same commit without it. A replay at the Maintainer's terminal can only measure what the code can be told to do, so each approach is code that is switched off until a replay's own copy switches it on. Keeping every switch off in the committed file means building them changes nothing a pull request meets.
