# 0167. The writes check holds four more routes: a namespace package, sys's modules, a class's attribute set from outside, and gh or git run from Python

Status: accepted. The Factory Builder's story of 2026-11-08, issue 596, "check_writes: further ways a write could be reached past the check, written to hide it", raised by the reads of issue 587, "Only the write steps call a write: a check that keeps GitHub writes to an allowlist of callers". It amends decision 0153's rows "Not held here: code written to hide a write" and "Not held here: `gh` run from Python".

## Decision

| What | Decided | Because |
|---|---|---|
| A namespace package | `tools/check_writes.py` reads a folder of modules with no package module of its own as the package Python imports it as. A dotted `import adapters.effects`, with no `adapters/__init__.py`, is a module of the repo, and what it names is read. A name such a package holds that is none of its modules cannot be read, and is a problem | Before, such an import was read as no module of the repo's, and what it reached was not read at all |
| sys's modules | A module that reads `sys.modules`, through `sys` imported under any name or re-exported from a module of the repo's, or imports `modules` or all of `sys`, is refused as one that loads a module by its name, unless NAME_LOADERS names it | A module taken from `sys.modules` by its name is one the syntax cannot follow, as `importlib` is |
| A class's attribute | An attribute set by `setattr` is refused. So is an attribute set on a class, in a plain or an unpacked assignment, to anything but text, from a function or from another module than the class's: a text constant a function's own name shadows is not text. A class's own body, and its module's top level, still fill it as before | A caller that names the class reaches what its own module gives it, and nothing set on it from elsewhere. A text constant set from a function reaches nothing, as `tools/trial_p50_stub.py` sets one |
| gh or git run from Python | A string that is `gh` or `git` alone, by a path or not, or opens a command line with either, is refused outside the Python RUNNERS names: ten files that run git to read or read a command they are given. A new one is the Maintainer's to allow, as a new caller is (decision 0153), and an entry that holds no command is refused, as a stale caller is | Run from Python, either may write to GitHub by no request of `adapters/github.py`'s, and holds no write verb as a whole string |
| Still not held | A RUNNERS function that runs git with arguments it is given can be handed a write's by its caller: ten modules on main reach such a function, through `release` in `harness/steps.py` and the hooks' helpers, so holding its callers to a list would list most of the harness; holding a runner to read-only commands is a change of its own. Neither is a class reached through another name, a class's attribute set through an alias, `type()` or `__class__`, nor an attribute of an instance or a key of a module's dict set from outside; `sys.modules` reached by `getattr`, `__dict__` or another module's `sys`; a command a shell runs from a longer string, or one named by a Windows path, an `.exe` or another case; an attribute set as a `for` or a `with` target; a command's name built from parts. Each is issue 640's, "check_writes: routes still open after issue 596, a runner's helper, a class or instance reached through another name, sys.modules by getattr" | The check is a net for code written plainly. These need a reading of values the syntax does not give, and are left to the review, as decision 0153 says, until that issue holds them |

## Why

The reads of decision 0153's change found four routes past the check, each taken only by code written to hide a write. On the Factory Builder's ruling they were filed rather than held in that change. Each is a pattern the syntax can name, so the check names it: none is used on main but by the ten RUNNERS, which read.
