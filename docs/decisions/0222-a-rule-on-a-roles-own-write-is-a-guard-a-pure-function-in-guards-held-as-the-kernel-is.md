# 0222. A rule on a Role's own write is a guard, a pure function in guards/, held as the Kernel is

Status: accepted. Decided for "The opening Run lands its one commit and opens the draft: the push write, apply's dispatch and `#342`'s writer (slice 2, S6)" (issue 838), by the Factory Builder's rulings of 2026-11-13. It adds to `docs/decisions/0188-a-roles-push-is-refused-where-it-touches-a-protected-path-or-a-model-lenss-input-read-from-its-bundle-before-any-token-is-minted.md`, whose row "The push's write lands the bundle's commits on the work branch, exactly that patch" waits on a writer: this says where the rule that writer keeps is built. No row of 0188 changes.

## Decision

| What | Decided | Because |
|---|---|---|
| The place | A package at the top of the repo, `guards/`. A rule on what a Role's own write lands is built there, as a function that is given what a port read and gives what may land, or the one reason, a code, why nothing may | Such a rule has many cases to test and changes as the writes grow. `harness/` is a model Lens's input, where every change is a person's to approve (0052), so the Harness is kept to the calls. `kernel/` and `adapters/` are where the Role that writes this repo's code may push, so a rule built there could be changed by the Role it binds |
| What a guard is not | A guard admits nothing. Whether a Run is wanted and whether a write is admitted stay the Kernel's Decisions, and whether a push touches a path a person must judge stays `harness/apply.py`'s (0188). A guard bounds the bytes of a write the Kernel has admitted, in `apply` | One place decides (section 2.4 of the design). The Kernel reads facts and never a Role's bytes; a guard reads a Role's bytes and never decides what happens next |
| Purity | `guards/` is held to every rule the Kernel is, by the same check under its own name: no I/O, no clock, nothing kept between calls, no `raise`, no special name, no number but 0 and 1, built-ins from the check's short lists. `tools/verify.py` runs it as "guards purity" | A function that reads nothing can be given every case in a test, and can hide none. It is the Kernel's own argument (0001), and the same check holds both |
| What it imports | `__future__` and itself, by its name. Never the Kernel, at a module's top or in a function, and never relatively. The Kernel is refused twice: by its name, and as any package that is not the guards' own | The Kernel is not protected whole, so nothing a guard decides may rest on it. With no relative import the package is imported in one way, and `from .. import x`, of which the Kernel's rules say nothing, reaches nothing above it |
| How the Kernel's rules read it | Before they run, the Kernel's name and the guards' are changed over at the head of each import the check parsed, so each rule reads the guards' imports of themselves as it reads the Kernel's of itself. A problem such a rule finds keeps the rule's own words, with a note: where it names a module an import names, the two names are changed over, and every other name is as written | One set of rules, read of two packages, cannot drift apart. A message rewritten for the guards said what was not true of a file or a parameter that bore either name |
| No rule written for a Kernel module by its name | No module of the guards is named as `kernel/terms.py`, `kernel/gate.py` or `kernel/brakes.py` is | The check allows the calendar's numbers in the Kernel's module of codes, and confines what its gate and its brakes import. Each is a rule for that module of the Kernel's, keyed by its file's name; read of a guard of the same name, the first would let it write a number but 0 and 1 |
| Who calls it | The Harness, in `apply`, with what a port read. A port never calls a guard for itself, and a guard calls no port | A port's write is then bound by a rule its own Role cannot have changed, on input the guard did not fetch |
| Its protection | `guards/` is a protected path, and one of `verify`'s inputs, since "guards/ is a protected path and one of verify's inputs before it holds a guard (`#838`)" (pull request 871), by the Maintainer's hand: listed before it held a guard, so the first one is never a file a Role could change | `config/hooks.json` is a model Lens's input. A package at the top of the repo must be one of `verify`'s inputs whole, so it could not arrive first by the Factory's route |
| What follows | The next pull request of issue 838 asks more of the package than its imports: that what Python imports of it is what the check read, and that a guard reads nothing off a value. Then the first guard, which applies a Role's patch. "The purity check does not ask that kernel/ is the package Python imports: a kernel.py at the root, or a compiled module beside a source, runs unread" (issue 851) holds the Kernel's half of those | The place and its check are decided once; each rule after is judged by its own tests. Until a guard is called, nothing rests on the package |

## Why

0188 admitted a push and left its writer waiting, with one residual: what lands must be exactly the patch the Run handed over. That rule has to live somewhere a model's change cannot reach it. The Harness is such a place, but every line there waits for a person, and a patch applied byte for byte is a few hundred lines with a mutant for each. The Kernel is pure and well held, but it is not protected whole, and it decides from facts, not from a Role's bytes. So the rule gets a place of its own with the Kernel's discipline, and the Harness keeps only the call.
