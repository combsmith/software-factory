# 0211. A pull request that left the open set is read for the window, so a write nobody matched keeps its alert

Status: accepted. The Factory Builder's ruling of 2026-11-13 on issue 787, a machine-user write nobody matched that closed its own alarm once its pull request merged. It amends decision 0112's row "What the entry gathers", where a pull request that has left is read as left once, by the pass after the one that last served it; the rest of the row stands.

## Decision

| What | Decided | Because |
|---|---|---|
| The fault | The entry read a pull request's writes while it was open, and once more in the pass after it left, as one that left, from the last record's list of what it served. From then on nothing read it, so a write on it that nobody matched dropped out of what reconciliation saw and `write_unmatched` cleared with no one matching it. The hand approval as the machine user on "A path only a person decides is listed apart from a Lens's inputs, and a change to it needs a person's approval" (pull request 779) (review 5883244267, 2026-11-12) alarmed until the pass after its merge, then cleared, and the issue that carried the alert closed itself | Decision 0198 has the Maintainer match each entry of the alert, so every entry is read for as long as it stands; it stood only until its pull request left |
| What is carried | `pass/1`'s `reconciled` gains `left`: each pull request a pass first read as left, merged or closed, stamped with that pass's time. Each record keeps an entry until the window, a day and `not_run_seconds` back (decision 0112), passes its stamp; one that leaves again is stamped again | The entry reads only the last two records, so what has left must be carried, as what is owed already is |
| What is read | Every pass reads each pull request `left` holds inside the window as one that left: its timeline, reviews, threads, check runs and comments, as `adapters/seen.py` reads a pull request that left. Its close, read when it was first read gone, stands though it is now older than the window; a timeline that names none is short | A write nobody matched then stays in what reconciliation sees, and keeps raising `write_unmatched`, whether its pull request merged or closed, until the window passes the write itself: each write is read in the window by its own time, so one made long before the merge alarms for less after it |
| A record written before | One with no `left` keeps none, and the next pass starts it from what it reads as left | The field is optional in `pass/1`, so earlier records stay readable |
| One read short | A pull request `left` holds that a pass reads short is owed, as any is, and read again as gone with its first stamp, never as newly left; owed once the window has passed its stamp, it is read no more | Else a transient refusal would stamp it again, and, past the window, a read that needs its close inside the window would never be whole again (the Claude review) |
| What remains | No one can match an entry to clear it sooner: an unmatched write alarms for the whole window, then clears whether or not anyone matched it. A way to mark an entry matched is a larger change, and is not built. A pass that cannot read the records before it carries no `left`, as it carries nothing owed; that pass is short and says so with `reconciliation_unreadable`, and what had left is not read again. `left` has no bound: each pull request in it costs a pass its reads for the window, so one that opens and closes many could slow the passes, as keeping them open already can | Named; the Maintainer's ruling on 0198 leaves the alert as it is, and decision 0098's limits bound a pass |

## Why

Reconciliation is the one check that a Factory identity wrote nothing it did not record, and the alert it raises is read entry by entry. A merge is exactly when a hand approval has done its work, so it is the worst moment for its entry to vanish; reading what left for the window keeps it in view as long as anything else reconciliation reads.
