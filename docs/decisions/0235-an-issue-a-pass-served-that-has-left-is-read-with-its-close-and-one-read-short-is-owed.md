# 0235. An issue a pass served that has left is read with its close, and one read short is owed

Status: accepted. The Factory Builder's ruling of 2026-11-19 on "A Factory write on an issue that closes before the next pass is never reconciled: issues that left are read" (issue 916), part b: `pass/1`'s reconciliation carries `left_issues` and `owed_issues`, optional, and a pass that could not list the issues carries those it served as owed, with reconciliation short. It completes decision 0230, whose row on an issue that left waited on this. It is built in three parts: the carry and the seen port's reading of an issue that left first, then the pass's reading of which issues left, which fills that row, then the pass's read of the repo for them; each part adds its rows below.

## Decision

| What | Decided | Because |
|---|---|---|
| Which issues have left | Those the pass before served, decided or left out unread, and those owed, that the issues this pass serves no longer hold. The listing is of open issues alone, so one not in it has closed, or left the served set | Derived from the record before and this pass's listing alone, as the pull requests that left are (decision 0063): nothing is stored apart |
| How one is read | As a pull request that left is: its timeline and its comments in the window, by the seen port, whole only with its close in the window; one a pass before read as left, inside the window, is read as gone, any close of it standing; past the window it is read no more. A merge is no issue's close | So a Factory label, comment or close on an issue that closed before the next pass is matched, or is the alert, `write_unmatched`, as "write_unmatched clears once the pull request it names leaves the open set, so a machine-user write nobody matched closes its own alarm" (issue 787) asked of a pull request |
| What is carried | Each issue first read as left is stamped in `left_issues`, as `left` stamps a pull request; each that left and could not be read whole is in `owed_issues`, and read again. An open issue served now and read short is not owed: the next pass reads it, served or left | A record with neither carries neither, as one written before them |
| How one is read first | By REST's read of the issue itself. Closed, it is read as above. Still open, left out of the issues served, as when `issues.served_from` moved, it is read as an open issue is, with no close. Answered 404 or 410, it is whole with nothing more read, only where the same token read the repo itself, by its full name, in the same pass; it is then named once in the view as information, `issue_gone`, its answer as the key. Any other answer is short: a 403, a 429, a 5xx, none at all, a body of another issue or with no state | Reconciliation that stays short for ever hides the real alert. A 404 or 410 is the end of what can be read there, where the repo still answers the token; where it does not, access may be what was lost (the Solution Architect's ruling of 2026-11-21, option A, read fail-closed) |
| What cannot be told | A transfer's 301 stays short: the transport follows no redirect for such a read and keeps neither its code nor its address, by design, so a 301 reads as no answer. An issue converted to a discussion stays short too: what REST answers for one is unverified. Telling both is "transport: keep a redirect's code so a transferred issue reads as moved" (issue 1095), with a trial | What cannot be told apart from a lost answer stays short (the Factory Builder's narrowing of the ruling, 2026-11-21) |
| A pass that could not list them | Where the tracking issue's number was not read, the issues' Apps could not be told, or issues are not served, none has left that can be told: every issue served before, owed or kept as left is owed again, none is read, and reconciliation is short. With nothing to owe, nothing is short | An issue not listed for want of a listing is not one that closed |

## Why

Before this, closing an issue was a silent way out of reconciliation for every Factory identity: a write on an issue that closed before the next pass, and the close itself, were never read.
