# NNNN. A boundary's check names a test, never a file, and a new or changed row names the mutant its test kills

Status: accepted. The Factory Builder's story "A boundary's check names a test, never a file, and a new boundary names the mutant its test kills" (issue 590).

## Decision

| What | Decided | Because |
|---|---|---|
| A test is named as a test | Wherever a rule names its check (a decision's Boundaries, an `AGENTS.md` rule, a lesson's Check, a standard's `Held by:`), `tools/check_context.py`'s `_held` refuses a check under `tests/`, as its path resolves, that names no test: a file, `path::` with no name, or a function whose name does not begin `test`. The test must exist, as before. The five that named a file are each given a test: two decision rows (0008's fifth, 0049's seventeenth), the root `AGENTS.md`'s simulator rule, `tools/AGENTS.md`'s hook rule and lesson L-25 | A file of tests passes for any rule, so a row that names one looks held when nothing in particular holds it |
| A row names its mutant | `tools/check_decisions.py` compares each record's Boundaries with the merge base, as it already does. A row new in the change, one whose Check changed, and any row that names a mutant, on every run, names one or more as `mutant: "<description>"`. Each must be in `tools/mutants.py`, change a file the row itself names in backticks that is not under `tests/`, each path read as the repo holds it, and list at least one test, each of them one the row names. A test is matched by its whole id, or by its module, one class and its name where the row gives no class; a module or a class is not a test | `tools/mutants.py` records, for each mutant, the file it changes and the tests it is run against, so whether a row's test notices its rule's break is read, not taken on trust |
| How such a mutant is killed | `tools/mutants.py` runs a mutant that a Boundary row names against the tests it lists, alone, never the whole suite after them. So it is killed only by a test the row names. Every other mutant runs as before | A kill by any other test would let the row's test look like the one that notices the break |
| What is not a changed row | A row main holds, as it stands. One whose Check differs only in that a file under `tests/` it named bare is now named by a test of that file, with the same mutants, the same wait and the same word that it is not held yet: so the five rows above are rows main holds. Any other change is a changed row, among them a rule that stops waiting or stops being not held yet | About 1,500 rows name no mutant, and they stay as they are. `verify` prints how many still name none |
| What is exempt | A row that waits on a planned part (`waiting on …`) or says it is not held yet, and whose every named test is marked `@pending`: it has no test that can kill a mutant. A row that also names a test that runs is not exempt | As `_held` already exempts them |
| What it reads | The mutants are read once in a run, by importing the tree's `tools/mutants.py`, and only when a row needs them. Mutants that cannot be read, or two that share a description, hold no row: the row is refused | About a tenth of a second, in `check_decisions`, which the hooks run in `make checks` after an edit and before a stop |
| What it does not hold | Whether the named mutant breaks the rule as the row states it, and whether each rule the Decision states has a row | Both stay with the review Role, PR-5 |

## Why

A record looked held whenever its row named something under `tests/`. A whole test file passed that rule, and so did a real test that held some other rule. The mutants already say which tests are run against which break. So a new row can be held to that mechanically: it names a break and the tests that notice it, the check reads both in `tools/mutants.py`, and the mutant run counts a kill by those tests alone. Rows already on main are left alone, so this asks nothing of the 1,500 rows written before the rule. A row once it names a mutant is read again on every run, so that the mutant cannot be taken away from under it.
