# 0114. A shim inherits secrets, and a Run's last job wakes the poller

Status: accepted. Trial P-55, asked by ruling 9 of "Workflows: the frozen entry shim, the poller, the Run's three jobs and the nudge, each held to its shape" (issue 196), run on 2026-11-01, failed its pass condition on two parts. These are their fixes, under the orchestrator's rulings of 2026-11-01. They amend its rulings 3, 4 and 5. They change, in decision 0057, the rows that a shim's job holds nothing but its call, grant, concurrency, `if` and `with`, that the poller wakes on the end of `sf-run`, and that no job but the pass job is granted a write; in decision 0043, that a Run's end restarts the chain through what the poller listens to; and in decision 0066, that a Run has three jobs. §4.9 gains a holder of the grant.

## Decision

| What | Decided | Because |
|---|---|---|
| A shim's secrets | Every shim's job holds `secrets: inherit`, in those words. A named secret on a shim, those words quoted, and any workflow with an event that is not a shim's are refused | P-55: a called job naming an environment read its secret only with `secrets: inherit` on its caller, and read nothing without it, where a job of the dispatched file read it. Under ruling 3's shim, `pass`, `run` and `apply` would each have started with an empty key |
| What that opens | The called Release file can name any secret of the repo or the org, and an environment's in a job that names that environment | Said plainly, since ruling 3 and L-37 refused this. The alternative is no reusable workflow for a job that holds a key, which gives up the channel |
| **Every key's guard is the tag rulesets** | With `secrets: inherit`, `factory release tags` (25183656) and `factory releases are immutable` (25996980) are what stand between a moved tag and every key. Both are recorded in `config/rulesets.json` and `tools/check_rulesets.py` holds them: active, over their tags, holding their rules, the first bypassed by the admin role and the release App by the data's id alone, the second by no one. Whether the live rulesets still say so is `tools/rulesets_drift.sh`'s, run by hand | An environment's branch policy is met by the caller's `main`, whatever commit the channel names: P-55's called job at a test tag read a secret limited to `main`. A file held word for word is held only as a pull request carries it, not at the commit a tag names. Without inherit, a moved tag read no key |
| The wake-up | `wake`, a Run's last job in `.github/workflows/run-jobs.yml`, and the approving act's in `.github/workflows/approve-job.yml`, word for word: `needs` the others, `if: always()`, and dispatches the poller. `sf-run` leaves the poller's `workflows:`, which keeps `factory` and `ci` | P-55: a Run dispatched by the pass's token woke nothing by `workflow_run` when it ended, twice, where a person's woke the poller within seconds. `wake`'s poller run was created 5 seconds after `apply` ended, and its pass began 10 seconds after |
| The grant it widens | `actions: write` on `wake`, and on `lane`, the calling job in run.yml and approve.yml, since a called job can be granted no more than its caller. §4.9 gave that to the poller's job alone. The token can also cancel or delete runs, or start a Run, since it reads as the pass's token does | `wake` holds no secret, no environment, no checkout and no input in either file, which the check says beside holding it word for word, so it never stands beside the approver's token or a key. Its one step is one fixed line. The other jobs each name their own grant, so the caller's gives them nothing. Each id is those files' alone |
| When it cannot | A dispatch that fails, or hangs past 60 seconds, says so and exits 0, so it does not fail a good Run, and that Run falls back to the backstop. It is the one exit 0 on a failure the check allows. A force-cancelled Run, where `wake` did not run, and by the same reasoning a lost runner, not tried, leave the next pass to the backstop. A runner lost on `wake` itself can fail a good Run, which is then counted so; that is the one new way to fail. Under a Pause it stands down, as the Controller's ruling on what a Pause stops has every dispatch do | The successor chain would see those too, at a pass about every 10 seconds for as long as a Run is open, up to about 180 for one Run. A wake costs one job, 4 and 9 seconds in the two rounds |
| The wait | A pass its own token started waits at least 30 seconds before it reads, and the gap where that is longer | `wake` dispatches from inside the Run, so the poller's run exists before the Run reads as ended: 2 and 3 seconds in the two rounds, and the pass's job began 5 and 6 seconds after the poller's run. A pass that read the Run as open would decide nothing and start no successor, and the item would wait for the backstop. A successor pays 30 seconds, and a Run's end is that much slower |
| How the pass reads it | A pass `wake` started is a dispatch by the workflow's own token, so `started_by` is `successor`, as §7.3 has it. So the health page's chain length, successors in a row, runs on through a chain that broke and a Run's end restarted, and a Run's end no longer shows as `own_repo` | The run reads `github-actions[bot]`, event `workflow_dispatch`, and no input can tell them apart, since the shim refuses one |
| What held | The lane: a second Run of an item started its `run` job 4 seconds after the first's `apply` ended, and another item's overlapped both. `if:`: `github.actor_id` reads 41898282 for the pass's token, true as a string and as a number; a person's dispatch, a Pause and a re-run are each skipped | As rulings 6 and 7 rest on them |
| What it answered | A run whose only job an `if:` skipped concludes `skipped`, on `workflow_dispatch`, and so does the job. `job.workflow_sha` names a called workflow's own commit with no grant, as REST's `referenced_workflows` does; `github.workflow_sha` is the caller's. 7 successor dispatches in a row ran with no stop, which is as far as it was asked | Ruling 14 and the records port's ruling 10 wait on these. Each job goes on checking out the tag, handing on the commit it got, until a change uses `job.workflow_sha` |

## Why

The trial ran the files' shape: the shims word for word but for the repo, the tag and the schedule, which would have started
passes nobody asked for; the called jobs with their needs, ifs, grants, outputs and environments, and probes for steps, since
the steps need keys. Both faults would have shown first on the live Factory, as a pass with no key and an approval that waits
for the backstop.
