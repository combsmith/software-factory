# NNNN. A machine user's approval is measured from the act that read the description, in the Kernel and the simulator's world alike, and one nothing anchors holds an edit

Status: accepted. Replaces `docs/decisions/0158-a-machine-users-approval-is-measured-from-the-act-that-read-the-description-and-one-nothing-anchors-holds-an-edit.md`. The Factory Builder's story of 2026-11-08, issue 608, "The simulator's world reads the description's anchor from the act's Run, and the Kernel's default goes", on the ruling of 2026-11-07 on issue 195, "The approving act: the machine user approves from a Run with no Engine, bound to the admitted commit". Decision 0158 holds that ruling; this record holds it again, but that the simulator's world reads the anchor as the Kernel does and the Kernel's default is gone. Like it, this amends decision 0135's anchor and the first clause of decision 0140's row "What it does not see".

## Decision

| What | Decided | Because |
|---|---|---|
| An act's approval | A machine user's approval is measured from when the latest `issue-approval` Run on its content made at or before it was made: its dispatch, which a re-run keeps, or its start where that is earlier or no dispatch is read. It is read from this item's run records | The approving act reads the description after its Run is made and before its approval lands. Measured from the approval, an edit in those seconds came before it and held nothing. A Run's start is its latest attempt's, so a re-run after the approval would have moved it past the read |
| A browser's approval | One with no such Run, where a record of this item began at or before it, is measured from its own time | Decision 0046 lets the Maintainer approve his own change as the machine user in the browser, and a person reads as they approve. Holding it would hold nearly every such pull request, since a reviewer App edits most descriptions once, seconds after opening (decision 0140) |
| One nothing anchors | One with no record of this item that started no later than it, with an act on its content started after it whose dispatch was not read and that is a re-run or one whose attempt cannot be read (`rerun_by_dispatcher` present), which may be the act that read, or with a record whose start cannot be read, is measured from before every time, so any edit holds the item (`description_edited_after_approval`) until a person approves after the edit, as before | Records expire oldest first, and an act's Run is made before its approval: it is not gone while a record made before it stays. A record reaches back by its start, which a re-run only moves later. With none, it may be an act's whose Run is past retention, and falling back to the approval's own time would open the gap again. A record list that cannot be read already defers the item as incomplete facts |
| The residuals | An item whose oldest retained record postdates a browser's approval holds on any edit, and needs a person to look; that fails safe. Two pass an edit unseen once the act's Run is gone: an act's Run a person deletes by hand while an older record stays; and a Run made while the act ran, which waits in the item's lane (section 2.4, rule 4) but whose record's start is when it was made (`trials/P-44.json`), once the act's Run is past retention and it is not. Issue 633, "A canary trial reads when a lane job began: the jobs API's job started_at beside the run's run_started_at", takes up the second, and decision 0158 named both | The first is only on an item older than the records' retention. The others need a person to delete a record, or the retention's edge to fall in the act's own seconds on an item older than it |
| A record in the approval's second | It reaches back, as one before it does, both as an act's Run and as a record older than a browser's approval | An act's Run is made seconds before its approval, and the simulator's world records its act's Run in its approval's own second. Another Run made in that second, while the act ran, is the residual named above |
| What it reads | The run records the Kernel already has: their `dispatched_at` and `started_at`, and whether `rerun_by_dispatcher` is present, which marks a re-run or an attempt that cannot be read. `facts/1` gains no field, so the held-out cases are unchanged | A record already says when each Run was made, and whether it was run again |
| The simulator | `description_anchor` takes the records by name, with no default, and `approval_anchor` has no branch for records not given: each caller gives the records, an empty list included. `sim/world.py`'s `edited_since_approval` dates each machine approval by `read_at`, in the world's own words: the start of the latest approving act's Run on its content that started no later than it; else its own time, where a run of the item started no later; else before every time. The world makes no record with a dispatch, a re-run or another item, and no start that is no time, so it has no branch for them | The default measured each approval from its own time, the anchoring this rules out, and was kept only for the world's test, which now gives the world's records. The world's act starts in its approval's own second, so every seed reads as before |
| What stays | Decision 0135's rule, the first approval since a person's look and never the latest, the outsider's anchor, and its handling of a second. Decision 0140's other clauses: an edit after the last pass and before the queue's merge, and an issue linked by hand | Only the anchor's time changes |

## Why

Decision 0140 named it: an edit after the approving act's last read and before its approval lands is timed before the approval, and holds nothing. The act re-reads the item and asks the Kernel again before it approves (decision 0055), so the only edit it cannot see is one in its own last seconds. When its Run was made is earlier than that read, so measuring from it errs early, and needs no new fact.

Decision 0158 kept a default for the simulator's world, whose act's Run starts in its approval's own second, so a reading it rules out stayed in the Kernel for one caller. Given the Kernel's reading, from its own records, the world needs no default.
