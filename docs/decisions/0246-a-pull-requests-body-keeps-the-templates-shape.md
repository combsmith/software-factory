# 0246. A pull request's body keeps the template's shape

Status: accepted. The Solution Architect's ruling of 2026-11-21, relayed by the Factory Builder, on the readability lane's plan, item 2, for "tools: check that pull request bodies keep the template's shape" (issue 1100). It adds to decision 0244 and changes none of it.

## Decision

| What | Decided | Because |
|---|---|---|
| The rule | A pull request's body holds the four headings of `.github/pull_request_template.md`, `## Why`, `## What changed`, `## What to look at` and `## Record and protected edits`: each once, in that order, each over some text. Other sections may stand beside them, and the checks-and-readers block is not required | Since 2026-11-21 the repo squashes with the pull request's body as the commit's message, so the body is main's log for good, as the title is (decision 0244). The same four headings let a reader find why a change was made in any commit |
| A heading | A line of up to three spaces, `##`, then nothing or a space or tab and the heading's words, a closing run of hashes dropped only after a space or tab, as GitHub's Markdown reads a second-level heading; a bare `##` is a heading of no words, and a section ends at any second-level heading. Line ends of any kind, LF, CRLF or CR, are line ends | The web editor saves CRLF and the desk reads LF; the same body must get the same verdict |
| What is hidden | A heading counts only on a line a reader sees whole. A code fence (three or more backticks or tildes, after any indent or list marker) hides what it holds until a fence of its kind, at least as long, with nothing but spaces or tabs after it; a backtick fence whose words hold a backtick is inline code and opens nothing. A comment, and a `<details>` block of any case, with attributes or nested, hides what it holds; one left open hides the rest of the body | A body may quote the template, or another body; what it quotes, or hides, is not its own shape. Reading an indented fence as one hides more, never less |
| Some text | Any character but whitespace that a reader sees, outside a hidden part, and not an empty list item (a bare `-`, `*`, `+` or number). "None." is text, and so is code in a fence. A heading held twice is read for each of its sections | The untouched template would otherwise keep two of its sections by its own scaffolding. Nothing but a person's words should keep a section |
| What is judgment | Whether "Why" is plain, and whether "What to look at" is honest. No check holds these | They cannot be told from the text alone |
| Where it is held | `tools/pr_title.py`, inside `check`, from the same read of the pull request as the title, called by the same one call in `tools/commits_are_the_maintainers.py` (decision 0244). The workflow does not change | The read already holds the body; a second module, call or read would add a second thing to protect and nothing to hold |
| What cannot be read | A body that is null, missing or not text refuses with its own code, `body_unreadable` | GitHub answers null for an empty body; a check that passes what it could not read holds nothing |
| The cutover | A pull request opened before 2026-11-23T00:00:00Z, by its `created_at`, is not read for its body. It is still read for its title, from 0244's cutover | The style was announced on 2026-11-21; this gives the lanes a day to write their queued bodies to it |
| What is printed | A code and the template's own heading names, never a word of the body. The desk's command, `python3 -m tools.pr_title --body FILE`, prints the same | The body is text from outside, and the job's log reads a line that starts with `::` as a command |
| The limit: a Role's drafts | When a Role is named to open drafts (decision 0215), the bodies it writes must keep the template's shape, or the record that names it must exempt them. Today only the Maintainer's account opens a pull request here | A draft's body is the model's (decision 0238); a rule its writer was never told would hold every draft |
| The limits of 0244 | A reopened pull request opened before the cutover stays out of scope; a body edited after a run read it is not read again until the next push or the merge group; and what can blind the commits check is what can blind this one | The body is read by the same call, at the same moments, as the title |

## Why

The template made bodies readable when people used it. Since the body is now main's commit message, a body out of shape is a commit message out of shape for good. The mechanical half of the shape, its headings and that each says something, is held where the title already is, at no cost in reads or workflow changes.

## Boundaries

| Boundary | Check |
|---|---|
| The template's headings are the check's; a body in shape passes, "None." is text, other sections and the details block are allowed | `tests/test_tools.py::test_a_body_keeps_the_templates_shape_or_says_which_part_it_breaks`, `tools/pr_title.py`, mutant: "the body needs no Why", mutant: "the body needs no What changed", mutant: "the body needs no What to look at", mutant: "the body needs no Record and protected edits" |
| Each heading missing, held twice or over nothing a reader sees refuses with its own code; any two swapped refuse as out of order, a heading held twice among them, and each of its sections is read; the untouched template keeps no section | `tests/test_tools.py::test_a_body_keeps_the_templates_shape_or_says_which_part_it_breaks`, `tools/pr_title.py`, mutant: "a missing heading passes", mutant: "a heading held twice passes", mutant: "an empty section passes", mutant: "a second section is not read for its text", mutant: "headings out of order pass", mutant: "an empty list item is text" |
| Fences: all four headings inside one refuse; a fence closes only on its own kind, at least as long, with only spaces or tabs after; inline code opens none; a fence in a list item hides what it holds | `tests/test_tools.py::test_a_body_keeps_the_templates_shape_or_says_which_part_it_breaks`, `tools/pr_title.py`, mutant: "a fenced heading counts", mutant: "a fence closes on a shorter one", mutant: "a fence closes on the other kind", mutant: "a fence closes on a longer one only", mutant: "a fence closes with any space after it", mutant: "inline code opens a fence", mutant: "a fence in a list item hides nothing" |
| Comments and details blocks hide their headings, whole, nested, of any case, with attributes, or left open | `tests/test_tools.py::test_a_body_keeps_the_templates_shape_or_says_which_part_it_breaks`, `tools/pr_title.py`, mutant: "a heading in a comment counts", mutant: "a comment hides nothing", mutant: "a comment left open ends at its line", mutant: "the checks-and-readers block hides nothing", mutant: "a nested block ends at its first close", mutant: "a block's open tag is of one case", mutant: "a block's open tag takes no attribute" |
| A heading is read as GitHub reads one: another level, four spaces or a tab in, or a hash run in its words is none; a bare `##` ends a section; CRLF and CR are line ends | `tests/test_tools.py::test_a_body_keeps_the_templates_shape_or_says_which_part_it_breaks`, `tools/pr_title.py`, mutant: "a heading of another level counts", mutant: "a heading four spaces in counts", mutant: "a hash run in the words is closing", mutant: "a heading of hashes alone keeps them", mutant: "a carriage return is no line end", mutant: "a lone carriage return is no line end" |
| Every problem is said, none holds a word of the body, and a body of the largest size is read in time | `tests/test_tools.py::test_a_body_keeps_the_templates_shape_or_says_which_part_it_breaks`, `tools/pr_title.py`, mutant: "only the first body problem is said", mutant: "a body problem says the body" |
| The body is the one read's, never the event's, on a pull request and on a merge group; a null, missing or non-text body refuses with `body_unreadable`; one opened a second before the cutover is not read for its body, one opened at it is | `tests/test_tools.py::test_the_body_is_read_on_both_events_from_its_cutover`, `tools/pr_title.py`, mutant: "the body is not checked on a merge group", mutant: "a body of no text passes", mutant: "a body opened at its cutover is not read", mutant: "the body's cutover is the title's" |
| The desk's command checks a body's file, says what it found, and prints nothing of the body | `tests/test_tools.py::test_the_desk_checks_a_bodys_file`, `tools/pr_title.py`, mutant: "the desk passes every body", mutant: "the desk passes a body it cannot read", mutant: "the desk's body command takes a lone flag" |
