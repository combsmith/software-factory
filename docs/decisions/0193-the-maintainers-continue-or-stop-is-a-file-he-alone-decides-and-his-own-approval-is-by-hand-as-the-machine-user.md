# 0193. The Maintainer's continue or stop is a file he alone decides, and his own approval is by hand as the machine user

Status: accepted. Working rulings 5 and 7 on "The ruleset switch: main requires the machine user's approval of the most recent commit, and slice 1's event is recorded" (issue 198), and the Maintainer's ruling of 2026-11-11, as the Factory Builder relayed it, that a change the Factory may not approve merges on his approval by hand as the machine user. It says what 0008's "The Maintainer's own approval never depends on the Factory running" means while he authors every pull request, and carries out 0191's row "What is not shown yet" as far as a record can.

## Decision

| What | Decided | Because |
|---|---|---|
| The record | `release/decision-points.json`, of schema `decision-points/1`, holds one entry for each decision point of the design's section "Stopping". An entry names its Release, what the Maintainer was shown beforehand, and his decision, its day and his login. The first, `first_release_on_next`, is recorded now; the first Consumer repo served is slice 3's to add, with its own measures | The design says the record is a file in the Factory repo, and gives it no form |
| Which Release, and which moment | The Release is the one that reviewed slice 1's event, as `release/fixtures/event.slice-1.json` records it. What is counted merged before that event merged | The design names the first Release on `next` that serves the Factory's repo, and no moment. The event is the merge slice 1 records as one that Release's approval let through |
| What he is shown | The pull requests merged into `main` before the event; how many of them he authored, and so read and merged himself; and how many changed a path `config/hooks.json` protects, as that list stood on the day of the read. They stand beside the design's starting figure of 40. Every merged pull request counts | The design asks for the count against the figure, and for the share a protected path explains. It gives no start date and no rule for another author's |
| Who decides | Only the Maintainer writes `decided`, `day` and `by`, the three together or none. `by` is the login `config/hooks.json` names him by, in any case of its letters, and where that file names nobody, nobody's decision counts. The day is the day the counts were read, or later. A session fills in what he is shown and leaves the three empty | The decision is his by the design, and he makes it on what he was shown. A file a session could decide would record the session |
| What passing the figure does | Nothing. No check reads the count against the figure | The design: passing 40 stops nothing; it is the signal to shrink the slice or to fall back on the proof of concept's reviewer |
| When the Factory cannot approve | The Maintainer's own approval is his approval by hand as the machine user, in a browser signed in to that account. Nobody is given a bypass. The order is the Pause; then a rollback of `next`, if an earlier Release served; and the hand approval only when no Release can serve. The skill `.claude/skills/cut-a-release/SKILL.md` says so. A session stops before the approval: it approves nothing, signs in to no account and sets no variable | GitHub counts no approval from an author (0191), so his own login cannot give it, and a bypass is what `examples/invalid/rulesets.main-with-a-bypass.json` refuses. A hand approval needs no Release, no Run and no stored token, so it does not depend on the Factory running |
| What is not held | The counts are read once, from GitHub through his login and from the repo's history, and no check reads them again. A hand approval is a write by a Factory identity with no recorded Effect, and nothing raises it until the Controller's reconciliation is built (0005) | `verify` reads the commit alone, and neither GitHub nor the history is in it |

## Why

The design gives the Maintainer two moments to decide whether the Factory goes on, and says the record is a file. The first moment came on 2026-11-11, when a Release on `next` reviewed a pull request to this repo and the machine user's approval let it merge. A decision that matters this much should be read from one place, be his alone, and show what he saw when he made it; a file a check holds gives all three, and a comment gives none.

From the switch, `main` merges nothing without a code owner's approval of the last push (0191), and the approval that counts for the Maintainer's own pull requests is the machine user's. If the only way to give it were the Factory's approving act, a broken Release could not be mended through `main`, which is what 0008 forbids. The Pause and the rollback come first because each leaves the Factory doing the approving; the hand approval comes last because nothing records it yet.
