# 0061. The pass's entry reads through the ports with a token of reads alone, and the last two pass records under a bound of their own

Status: accepted. A working ruling of 2026-10-22 for "Workflows: the shims, the pass and the Run's three jobs" (issue 196), its PR 2a, as the orchestration session split it, with the rulings on "Controller: one pass reads, decides, records, dispatches, writes the view and raises the reconciliation alert" (issue 193), its PR 2's ruling 10 and the orchestration session's ruling (e) on the pass records' bound. The Maintainer may overturn it in review. It adds to `docs/decisions/0045-the-transport-follows-one-redirect-an-artifacts-download-to-githubs-artifact-storage-alone.md`, whose bound it widens for one artifact, to `docs/decisions/0043-a-scheduled-tick-is-a-backstop-of-hours-the-relay-carries-w-2-and-a-pass-records-what-started-it.md`, whose read gap the entry waits out, and to `docs/decisions/0036-a-run-listed-before-its-name-is-unidentified-and-defers-every-admission.md`, whose records it reads.

## Decision

| What | Decided | Because |
|---|---|---|
| The entry | `controller/__main__.py`, run as the `controller` module, the one module of `controller/` that reads the clock or the environment. It reads the Release from `RELEASE`, its own run's id from `GITHUB_RUN_ID` and the Controller App's key from `CONTROLLER_APP_KEY`, and writes the pass record, the plan of writes and the view's three files, as JSON, to `OUT`, inside the directory it runs in. What it prints is a code | Every other module of the pass stays a function of what it is given, so a pass can be replayed (§3.4) |
| Its token | Minted for the home repo alone, with every permission `config/apps.json` grants the Controller's App for a `read:` need, at read, and no write, and revoked when the pass ends, whatever happened. The pass records are read under `read:records.artifacts`, which the App holds | The pass reads; the writes are the effects step's, through their own credentials (0051) |
| The pass records before it | The last two passes' records, `adapters/passes.py`: runs of the poller's file in the home repo, from its default branch, completed, by the schedule, a dispatch or the end of a run, this pass's own run passed over, newest first, one page of 20. Each is the one artifact named `pass`, a zip of one file, the record as JSON. A pass that uploaded none is passed over; one past its retention ends the reading. Anything that cannot be read makes the records unreadable, never fewer, and so does a page read through with fewer than two found while GitHub counts more | The read gap, `passes_since`, the not-run alert and the successor read no further back (the Controller's ruling 10, named in the Status). The view's ages and the health window cover those two until the feed story keeps them cheaper |
| The pass record's bound | The one artifact downloaded under a wider bound than 0045's 64 KiB: 1 MiB zipped, as listed and as downloaded, and 8 MiB read out of the zip. The transport takes a download's bound from its caller, 64 KiB unless asked, and one of those two alone; nothing but a download carries one. Every other artifact keeps 64 KiB | A pass record holds the facts of every open item, which no outcome's bound fits (the orchestration session's ruling (e)) |
| What started it | Its own run, read by its id: its event, its actor by id and type, and its attempt. One that cannot be read, of another id or another repo, is read as no run, and `started_by` makes it a dispatch | What started a pass is read from its run, never from anything a dispatch carries (0043) |
| The open pull requests | `adapters/items.py`: the home repo's, by GraphQL, `pullRequests(states: OPEN)`, a hundred to a page in the order opened, ten pages at most. Whole only when every page was read, as many as GitHub counted on every page, each once. Read short, nothing is decided: the pass writes nothing and fails, and the not-run alert reports it | A list read short is unreadable (L-53); a pull request not read is never one that is not open |
| Each pull request | `adapters/facts.py`'s snapshot. One that cannot be read is left out of the pass by its item, as one alert. Its accounts are `config/controller.json`'s: the Maintainer, the machine user `accounts.approver`, the Lens Apps `accounts.lenses`, the Factory's authoring Apps `accounts.agents` and the dependency bots `accounts.dependencies`, each by id, from the trials that recorded them. A Lens or an App no trial has recorded is not listed, so its acts are no Lens's and its pull requests no agent's | An account is told by its id, never by its spelling (0005); one not yet recorded fails closed, as `outside` or `app` |
| Not read yet | Issues: the issue Lifecycle's port is not built, so none is read and none is decided. The facts' own read dates and the window's usage, which no port reads: the pass record holds the run records' reads alone | Each waits on the story that holds its port |
| Read, and refused until the grants | The token holds only what the App is granted today. `FACTORY_PAUSED` needs the variables' read, so the Pause reads unreadable and nothing is admitted. A pull request's closing issues need `issues: read`, which no need in `config/apps.json` names yet, so a pull request that closes an issue cannot be read whole and is left out of every pass. Both come with the Maintainer's change to the App's registration that decision 0056 waits on, and the need is added to `config/apps.json` with its trial | Each fails closed: nothing is admitted or decided on a read the token may not make |
| Its end | The token is revoked whatever happened; one GitHub did not revoke fails the step, `token_not_revoked`, after the pass is written. `OUT` must be an empty folder, and every file is made new, never through a link already there | A read token left live is reported, and the step writes nowhere but where it was told |

## Why

The workflows' pass job runs the pass, and the Controller's ruling 10 gave it to the entry to read what no port read: the Pause, the pass records before it, and the pass's own run. The entry is built ahead of the workflow that runs it, so the workflow's PR only wires it. A pass record is a few hundred kilobytes once there are open pull requests, and 0045's bound would make every pass after the first unreadable.

## Boundaries

| Boundary | Check |

| A pass record alone is downloaded under 1 MiB, and read out to 8 MiB | `tests/test_adapters.py::test_a_pass_record_alone_is_downloaded_under_a_wider_bound` |
| What started a pass is read from its own run | `tests/test_adapters.py::test_a_pass_is_started_by_its_own_run` |
| The open pull requests are whole only when each counted was read once | `tests/test_adapters.py::test_open_pull_requests_are_whole_only_if_each_was_read` |
| A pass record a trial downloaded is read as the port reads it | not held yet: `tests/test_adapters.py::test_a_pass_record_a_trial_downloaded_is_read_as_the_port_reads_it` |
