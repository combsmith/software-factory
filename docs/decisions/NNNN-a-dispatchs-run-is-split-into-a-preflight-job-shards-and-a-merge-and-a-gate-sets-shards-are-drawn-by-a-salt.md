# NNNN. A dispatch's run is split into a preflight job, shards and a merge, and a gate set's shards are drawn by a salt

Status: accepted. The Factory Builder's rulings of 2026-11-08 (e) and of 2026-11-09 (a) to (d) on issue 611, "A case's head is read from the private home, pinned by its hash, and the run is sharded": this is the second of its two pull requests, the run sharded; the first read each case's head from the home. It amends decision 0170's row "When", where it says a gate set's preflight is asked in the run step before the set's cases, which a job of its own now does; decision 0164's row "The seal", where it seals one ledger and binds it in the report and names the job's one output, `ledger_sha256`, which the merge job now sets; and its row "The upload", where the ciphertext is the one artifact `eval-ledger`, which is now each part's, `eval-ledger-<part>`. Nothing else in either changes.

## Decision

| What | Decided | Because |
|---|---|---|
| The parts | `.github/workflows/eval.yml` holds three jobs. `preflight` asks a gate set's preflight, and nothing for a development set, which has none. `eval`, a matrix of the shards `config/harness.json` names, `eval_shards`, four, needs it, and each shard asks its share of the set, with a time limit of its own and `fail-fast: false`. `merge` needs both and runs whatever became of them, `if: always()`, holds no credential and no environment, and writes the one report from what each part uploaded. Each job plans as its part, `EVAL_PART`; a part the configuration does not name is `part_unreadable` | The issue's: one time limit for every case, serial, could not hold a set of forty or more. The Factory Builder's ruling (e): four shards behind one preflight, since four preflights would raise false stops to about 1.2% a run, and about 3.6% across a pool of three |
| Which cases a shard asks | A development set's case is the shard of its place in the manifest, modulo the shards, so each shard's mix of kinds is even. A gate set's is the shard of the sha256 of a salt the home keeps, `<role>/<set>.salt`, read with the home's token at the fetch, the run's id and attempt, and the case's id, modulo the shards. A gate set with no salt, or one not 16 to 256 bytes, stops the fetch, `no_shard_salt`, a code its seating must satisfy | The Factory Builder's ruling (a): a part's counts by kind, over a partition anyone can compute from the public manifest, would tell which cases are of which kind, which decisions 0094 and 0099 keep from the public. There is no private channel between jobs, so the partition is made unknowable instead |
| What a part writes | Each part's `run` step writes `eval-part/1` where the upload finds it, `eval-part-<part>`: how many it was given and passed, of each kind and of the blocking cases how many and how many passed, its natural and constructed counts, each code of a case not read, its usage and its models, and for the preflight its counts apart. A development set's part lists its cases as its report does; a gate set's lists none, and its cases with their Results go to a ledger of the part, under a salt of its own, sealed by that part's `seal` and uploaded as `eval-ledger-<part>`. No step's line, and no gate set's part, names a case | Every word the report says of its kinds is said from summed counts, as `split_ok`, `kinds_pass` and `blocking_pass` say it of the whole set, so the merge needs no case and no credential |
| The merge | The merge downloads every `eval-part-*`, reads each as `eval-part/1` of this run's Release, commit and set, and writes `eval-report.json`, uploaded as `eval-report` as before, so the Release's gate reads it unchanged. A part not there, not this run's, or of another part is none; its cases are `unanswered`, a fault of the run, and then no kind can be read, nor the split. A preflight that stopped leaves no shard to run, and the report says so, `preflight_failed`. The judge then judges the report as before | A shard that failed faults the run, as the issue's done-when asks |
| The preflight's job | It judges what it wrote: a preflight that `preflight_stops` fails the job, by its counts and codes, so no shard is asked | Decision 0170's stop, kept before any held-out case is asked |
| The ledger and the output | A gate set's report holds `ledger` as a list, each part's salted and sealed sha256, the preflight's first; a whole run's holds one, `whole`. The gate refuses a part named twice, or a whole run's beside a part's. The run's one output, `ledger_sha256`, is set by the merge step alone: the sha256 of the canonical JSON list of the parts' sealed hashes, in the report's order | The Factory Builder's ruling (c): one string output for every reader, the detail in the report. A matrix's outputs are its last writer's, so no shard sets it |
| The download | `actions/download-artifact` by its commit, the one already pinned in this repo's workflows, the merge job's alone | The Factory Builder's ruling (b) |
| A run not split | Where no part is named, each step runs the whole set and writes the report itself, as before | So a run, or a test, of one job reads as the merge of its parts does |
| Residual: kind counts of unknown subsets | Each gate set part still publishes its counts by kind, of a subset of the set no reader can name: across runs, and across a pool of three, these are counts of different unknown subsets | The Factory Builder's ruling (a), stated as a residual |
| Residual: a part's timing | A shard that runs out of time leaves nothing, and its cases are `unanswered`: the run is faulted, never read as the reviewer's | A shard's limit is its own; a slow one fails closed |

## Why

A dispatch over a set of forty or more cases ran them one after another, under one time limit, in one job: a set larger than the limit, or a slow Engine, faulted the run however the reviewer did. Split into shards behind one preflight, each shard has its own limit and they run side by side; the merge, holding no credential, makes the one report the gate reads. A gate set must not tell which of its cases is which kind, so its shards are drawn by a salt no reader has, and each part of it publishes counts alone.
