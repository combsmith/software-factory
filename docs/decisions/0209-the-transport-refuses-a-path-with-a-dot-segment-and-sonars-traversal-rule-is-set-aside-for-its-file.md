# 0209. The transport refuses a path with a dot segment, and Sonar's traversal rule is set aside for its file

Status: accepted. The Factory Builder's ruling of 2026-11-13 on "SonarCloud: code security review (pythonsecurity)" (issue 725), and the Maintainer's of 2026-11-12 that a confirmed false positive may be set aside in the repo.

## Decision

| What | Decided | Because |
|---|---|---|
| The finding | SonarCloud's one finding, pythonsecurity:S7044, "API Traversal via file content in Live.send()", is of the line the live transport sends a request on, reached from the eval job through `adapters/heldout.py`. On that flow it is a false positive: `case()` fullmatches the Role and the case's id, and `home()` the owner and the name, before the path is built | Sonar's taint engine reads no fullmatch as a sanitiser |
| What was real | The transport held a path's host and no segment of it, so that line was safe only caller by caller. Some callers reach it with a part only its source holds: the event payload's repo in `tools/commits_are_the_maintainers.py`; the home's branch and the home's repo from the Controller's configuration, whose schema admits a segment of two dots; and a pull request's base ref. None is an outsider's text today | A mark on the line would have silenced every rule there for every caller, while only one caller was shown safe |
| The fix | The live transport refuses to send a path any segment of which is one dot or two: plain, percent-encoded in either case, or behind an encoded slash or backslash. The query is split off before the path is decoded and is no path, and a dot within a name is no segment. It refuses a path with a hash, a space or a control character too. `sendable`, called by `Live.send` on every request | GitHub resolves a dot segment within a contents path: on a public repo, a path through a missing folder and two dots answered the file beside it, and did not climb out of the endpoint. What follows a path's last hash is dropped as the request is made, so a segment after an earlier one would be sent unread; a tab or a newline is stripped before a path is read |
| Where it is held | Where a request is sent, not where it is built: `request` is unchanged but for refusing, as Unanswered, a path that cannot be read as one | Each port's own refusal of its parts is told from the transport's by its tests, which hand the port a stand-in for the transport. Refused in `request`, the transport's refusal answered for five ports' own, and their mutants survived |
| What grounds it | Reads of a public repo with no credential on 2026-11-12: no trial, and no fixture. Five of them answered 404 for paths that would climb out of an endpoint; one answered the file for a dot segment within a contents path | The refusal needs no trial to be safe: no path the Factory builds has such a segment |
| What it does not hold | A part that holds a slash or a question mark of its own, which names another endpoint or a query with no dot in it: each port that takes a part from outside holds it, as the held-out port does, and the callers named above do not. Nor an encoding it does not decode: a percent-encoding of a percent, a semicolon and a path parameter after two dots, an overlong or a full-width dot, an encoded NUL, space or tab beside the dots. Each is a dot segment only to a server that reads it so, and nothing shows GitHub's does | The transport cannot tell a caller's slash from a part's |
| The held-out port | Unchanged. Its test refuses three more inputs: an id with a slash, an id with a percent, and a home's name with a percent | Three mutants of its patterns survived |
| Sonar | `sonar-project.properties` sets pythonsecurity:S7044 aside for `adapters/github.py` alone, in the form the file already holds. Every other rule stays live on it, and no NOSONAR is written there | A line's NOSONAR silences every rule on it. The finding is of the line every request passes, so the rule is set aside for the file whose transport holds the path |
| Residual | A port still to be written that puts an unheld part into a path is no longer flagged by that rule in this file | The transport's refusal stands in for it for a dot segment, and each port's own tests hold its parts |

## Why

The finding was a false positive on the one flow it named, but marking it so on the line would have hidden the same rule, and every other, for each of the hundred or so requests sent there. What the rule pointed at was real: nothing at the sink held a path's segments. Holding them there makes the transport safe against a dot segment whoever calls it, which is what lets the rule be set aside for the file, and only that rule.
