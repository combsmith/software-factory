# 0250. An issue's references and links are cut past their one page

Status: replaced by `docs/decisions/0000-an-issues-reads-are-bounded-and-a-read-cut-short-calls-a-person.md`, which holds the rule in force.

## Decision

| What | Decided | Because |
|---|---|---|
| A timeline's bound | The issues port reads an issue's own timeline, and each linked pull request's, to ten pages of a hundred events at most (`BOUND` in `adapters/timeline.py`). A tenth page that names an eleventh leaves the timeline not whole, and the eleventh is never asked. It reads an issue's linked pull requests only while there are 25 at most to read (`CANDIDATES` in `adapters/linked.py`); past them it reads none, and the list is not whole. The issue's references, and its timeline of links, closes and cross-references, are read in one page each; more than a full page holds is cut too, and what was read is read on; a page not full that says there is more is a read short, not a bound | Anyone can comment on an issue or a pull request, or open pull requests that name it, and a read with no bound, again on every pass, is an amplification an outsider controls (the security read of S3 PR2e) |
| A read past its bound | The issue's facts say so, `timeline_bounded` in `issue-facts/1`, whichever read the port cut: the issue's own timeline, beside `complete.timeline` false, or a linked pull request's timeline, or the pull requests past 25, or the references or links past their one page, beside `complete.linked` false. The issues' Kernel defers it `timeline_bounded`, before any list read short, a closed issue's too, and calls a person. A flag that is not exactly true or false is a gap in the timeline, `facts_incomplete`, never read as within the bound | A read short mends itself at a later pass; one past its bound only grows, and pass records keep a pull request once seen with its keyword. A person must see why the issue waits, so it is its own code, and calls one: a pull request's author who comments past the bound on their own pull request must not stall the issue in silence (the Factory Builder's re-ruling (A) of 2026-11-19) |
| The worst case of one read | One issue's read costs at most 25 × 11 + 14 = 289 requests: the issue, its timeline's ten pages, its edits, its links, and its second read, then each of 25 pull requests and its timeline's ten pages; and beside them one permission read for each login acting in what was read that the pass has not asked of, at most one an event, so a thousand accounts that each comment once cost a thousand more | The number is configuration; changing it is a change to a protected path. A budget that cut a read short would leave that issue read short at every pass that reached it last |

## Why

Decision 0234 bounds an issue's timeline and its linked pull requests. Building the bound showed two more reads an outsider can grow, the issue's references and its timeline of links, each read in one page, and a permission read for each new login; this record bounds the first and counts the second.
