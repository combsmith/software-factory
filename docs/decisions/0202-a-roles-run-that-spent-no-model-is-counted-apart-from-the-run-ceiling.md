# 0202. A Role's Run that spent no model is counted apart from the Run ceiling

Status: accepted. The Factory Builder's rulings of 2026-11-12 on "A Run that ended environment does not use up the item's run ceiling" (issue 757): a bound apart, for the Runs that failed before their Engine step started, which `docs/decisions/0201-a-runs-outcome-says-whether-its-engine-step-started.md` makes the run record say. It amends decision 0116's row "Attempts and the ceiling": a Run GitHub started no job of still counts toward the automatic pause, and is no attempt, but it no longer counts toward the Run ceiling. It adds a limit to `config/defaults.json`, so the Maintainer approves it by hand.

## Decision

| What | Decided | Because |
|---|---|---|
| A Role's Run that ended `environment` before its Engine step started (`engine_started` false) | Counted toward `max_environment_runs_per_item`, 30, since a writer acted, and not toward `max_runs_per_item` | It spent no model. During the runner DNS outage of 2026-11-11 ("A Run's CLI install fails whole when the runner's Ubuntu mirror cannot be resolved", issue 743), such Runs used up the ceiling of 10 on five pull requests, and each then needed a writer's comment |
| A Role's Run GitHub started no job of, with no outcome (`never_ran`, decision 0116) | The same | It ran nothing at all |
| A Role's Run that reached its Engine step, or does not say | Unchanged: toward the Run ceiling, whatever its outcome or reason, `environment` among them | It may have spent on the model. An item can end its own Run `environment`, since `engine_timeout` and `run_failed` at the step limit come after the model read it, and section 3.10 says a timeout cannot tell a slow provider from a slow item. Counting such a Run apart would let an item buy model Runs past the cost ceiling (FR-39) |
| The bound | 30, three times the ceiling | A Run that failed before the Engine spent runner minutes alone. The bound only ends a cause that never lapses on one item, which the automatic pause cannot see, so it may be set higher than the cost ceiling |
| Exclusion, with no bound apart | Refused | The automatic pause needs faults on 2 items, so one item's lasting fault would be sent again at every pass |
| An act's job that did not land: an approval, a resolution, an enqueue or a dequeue | Unchanged: toward the Run ceiling, whatever its fault, and never apart | The automatic pause stops no act, so the ceiling is all that keeps an approval failing for an expired token from being issued for ever (decision 0003) |
| Any other outcome: the item's, capacity's, superseded, or none | Unchanged: toward the Run ceiling. So is a Run whose word beside an outcome says it never ran: the outcome is read, as the pause reads it | Only a Run that spent no model moves apart |
| The Hold | `environment_ceiling`, given only after the Run ceiling is asked, so the Run ceiling is named where both are reached. It needs a person, who is asked what `run_ceiling` asks: renew the allowance or close (`config/feed.json`). A writer's action renews both counts | It is the same remedy: a person who sees the cause has gone, or closes the item |
| The Lifecycle | `max_environment_runs_per_item` is a counter for each item (`tools/check_lifecycle.py`). A Hold at it names it as its bound: from verifying, addressing or adjudicating by the Factory, and from verifying by a Lens or the platform, where a check's failure or a conflict asks for a Run the bound forbids | Every cycle with no person in it keeps a bound |

## Why

The Run ceiling held a review that never happened. Every Run on four pull requests failed at the CLI install, and each ended `held: run_ceiling` with nothing of its content judged. The automatic pause had already slowed the dispatches to about one an hour. A new head did not renew the count, since a push is no writer's action (`adapters/timeline.py`'s `ACTIONS`), so only a person's comment did.

A first version counted every `environment` Run apart. The security pass showed that an item can cause `environment` itself after the model has read it, so that version would have let a slow or hostile item buy 20 more model Runs. The run record now says whether a Run's Engine step started (decision 0201), and only a Run that never reached it moves apart.

The Lifecycle still terminates. A Run that spent no model makes no transition: it leaves the item where it was, and the Runs it causes are what the bound apart counts. Across items, the automatic pause slows a lasting outage to about one try an hour, so 30 holds an item after about 30 hours of outage, where 10 held it after about 9 (decision 0116). On one item alone, where the pause sees nothing, the bound apart is what ends it.

It costs two things, both accepted. **An item may be dispatched up to 40 times between writers' actions,** 10 toward the ceiling and 30 that spent runner minutes but no model. **A lasting outage still ends in every item's Hold,** now later, and each Hold still needs a writer. A Run whose outcome says nothing of its Engine, as one written before decision 0201, counts toward the ceiling as before.
