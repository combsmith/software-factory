# 0223. A person's resolution of a thread a Role opened is a write reconciliation matches to the Kernel's act that named the thread

Status: accepted. The Factory Builder's rulings of 2026-11-14 on "No check holds the hand's part of resolving a Lens's thread in slice 1: nothing notices a resolution the Kernel's act did not name" (issue 854). It widens decision 0061, which reconciles the writes of Factory identities, by one write of a person's, and gives decision 0212's row "What holds the hand" a check. The Maintainer may overturn it in review.

## Decision

| What | Decided | Because |
|---|---|---|
| What is read | `adapters/seen.py` reads a resolved thread whose resolver is no Factory identity, and whose first comment was made by a Role's own account, as a write by `hand`: a resolution, keyed by the thread's id. A person's resolution of any other thread is no write, as before, and an identity's is its own whoever opened the thread. An opener or a resolver that cannot be told, a first comment not said to reply to none or an account whose id or type cannot be read, leaves what was seen short and is no write | The Kernel takes a person's resolution as closing a Lens's Finding (`kernel/gate.py`), and every session writes as the Maintainer's account, which decision 0212 lets carry out the Kernel's act until the queue App exists |
| What it is matched to | The Decision of the last pass record before that decided its item: an act, `resolve_thread`, whose evidence names the thread. A pass that did not decide the item, which it could not read, says nothing of it. Anything else is unmatched | The last pass is the one whose check stands on the pull request's head. An act an earlier pass named and the last did not is of a head that has moved |
| An alert of its own | An unmatched one raises `hand_unmatched`, not `write_unmatched`, by the Factory Builder's ruling that it is an alert and not information as a merge by override is. The tracking issue is edited only when its causes change, and a hand's resolution stands for as long as its pull request is open: under one name it would hide an identity's write nobody recorded. Neither alert feeds the automatic pause, which reads Runs' faults alone (`controller/pass_.py`) | The Factory cannot tell the Maintainer in person from a session writing as his account, so this is the write it must notice, and it must not cost the alert decision 0061 raises |
| How long a match holds | A resolution is seen at every pass. Once matched, the thread's id is carried in the pass record, `reconciled.hands` of `pass/1`, stamped again at each pass that sees it, and kept for the window where a pass does not | The pass that named the thread is soon none of the records before |
| One nobody named | Is not carried. It is unmatched at every pass that sees it, until the thread is open again or its pull request has left for the window | The remedy is to open the thread again, and the Kernel then reads it as it stands |
| What no record can judge | Where nothing says whether an act named the thread, reconciliation is short for that pass, `reconciliation_unreadable`, the thread is carried, and the view names it, `hand_unjudged`, as information: with no pass record before, which is also what a pass makes of records it could not read; with a last record that carried no `hands`, written before this rule or by a Release without it; and with no record before that decided the item | A thread resolved by hand before this rule would otherwise raise the alert for as long as its pull request is open, and so would every matched one after a pass that could not read the records before it. What is waved through is named, so it can be looked at |
| What is not held | The Maintainer's own resolution of a Lens's thread, in person, raises `hand_unmatched` too, until the pull request leaves and for the window after: a day and the time a pass may not run. A resolution made in a gap no record can judge is carried without an act, named once in the view and never again. A second hand's resolution while one stands changes no cause. The comment decision 0212 asks of the hand is not read, and it renews the Run ceiling and the attempts on the item. A thread once named, opened again and resolved again inside the window is matched by what was carried. A matched resolution does not lapse when the head moves again: the issue's case, a push back to the content the Finding was raised on, stands as it was. A thread whose first comment was deleted reads its next as its first (trials P-49 and P-53). A Release without this rule cannot read a record that holds `hands` or `hand_unmatched`: after a rollback its first passes read no record before | Each needs who acted, what GitHub no longer holds, or what the Kernel would say now, and reconciliation is given none of them |

## Why

Decision 0212 let a session carry out the Kernel's `resolve_thread` by hand and said no check held the hand. The gate cannot: it reads any resolution by a person with write access as closing a Lens's thread. Reconciliation is where the Factory compares what was written with what it decided, and the pass record before holds the act and the threads it named.
