# 0223. A person's resolution of a thread a Role opened is a write reconciliation matches to the Kernel's act that named the thread

Status: accepted. The Factory Builder's rulings of 2026-11-14 on "No check holds the hand's part of resolving a Lens's thread in slice 1: nothing notices a resolution the Kernel's act did not name" (issue 854). It widens decision 0061, which reconciles the writes of Factory identities, by one write of a person's, and gives decision 0212's row "What holds the hand" a check. The Maintainer may overturn it in review.

## Decision

| What | Decided | Because |
|---|---|---|
| What is read | `adapters/seen.py` reads a resolved thread whose resolver is no Factory identity, and whose first comment was made by a Role's own account, as a write by `hand`: a resolution, keyed by the thread's id. A person's resolution of any other thread is no write, as before, and an identity's is its own whoever opened the thread. An opener that cannot be told from a Role's leaves what was seen short: a first comment that replies to another, or that GitHub does not say replies to none; no comment; an account that cannot be read | The Kernel takes a person's resolution as closing a Lens's Finding (`kernel/gate.py`), and every session writes as the Maintainer's account, which decision 0212 lets carry out the Kernel's act until the queue App exists |
| What it is matched to | The Decision of the last pass record before that decided its item: an act, `resolve_thread`, whose evidence names the thread. A pass that did not decide the item, which it could not read, says nothing of it. Anything else is unmatched, and raises `write_unmatched` as any write does, by `hand` | The last pass is the one whose check stands on the pull request's head. An act an earlier pass named and the last did not is of a head that has moved |
| How long a match holds | A resolution has no time, so it is seen at every pass. Once matched, the thread's id is carried in the pass record, `reconciled.hands` of `pass/1`, stamped again at each pass that sees it, and kept for the window where a pass does not | The pass that named the thread is soon none of the records before |
| One nobody named | Is not carried. It is unmatched at every pass that sees it, until the thread is open again or its pull request has left for the window | The remedy is to open the thread again, and the Kernel then reads it as it stands |
| What no record can judge | With no pass record before, or one written before `hands` was carried, a pass that sees such a resolution is short, `reconciliation_unreadable`, once, and carries the thread | A thread resolved by hand before this rule would otherwise raise the alert for as long as its pull request is open |
| An alert | By the Factory Builder's ruling it is an alert, not information as a merge by override is. `write_unmatched` joins the alert's causes alone: the automatic pause reads Runs' faults and nothing of reconciliation (`controller/pass_.py`), so one such write defers no Run and stops no act | The Factory cannot tell the Maintainer in person from a session writing as his account, so this is the write it must notice |
| What is not held | The Maintainer's own resolution of a Lens's thread, in person, raises the alert too, until the pull request leaves and for the window after: a day and the time a pass may not run. The comment decision 0212 asks of the hand is not read. A thread once named, opened again and resolved again inside the window is matched by what was carried. A matched resolution does not lapse when the head moves again: opening the thread again is still the hand's, as decision 0212 asks | Each needs who acted, or what the Kernel would say now, and reconciliation is given neither |

## Why

Decision 0212 let a session carry out the Kernel's `resolve_thread` by hand and said no check held the hand. The gate cannot: it reads any resolution by a person with write access as closing a Lens's thread. Reconciliation is where the Factory compares what was written with what it decided, and the pass record before holds the act and the threads it named.

## Boundaries

| Boundary | Check |
|---|---|
| A resolved thread a Role's own account opened, resolved by an account that is no Factory identity, is read as a hand's write; of any other thread it is none; an identity's resolution is its own; an opener that cannot be told leaves what was seen short | `tests/test_reconcile.py::test_a_persons_resolution_of_a_thread_a_role_opened_is_read_as_a_hands`, `adapters/seen.py`, `schemas/seen.schema.json`, `tools/mutants.py`, mutant: "a person's resolution of a Role's thread is nobody's write", mutant: "a person's resolution of anyone's thread is a hand's", mutant: "an opener that cannot be told leaves nothing short" |
| A hand's resolution is matched only to the act `resolve_thread` of the last pass before that decided its item, where its evidence names the thread | `tests/test_reconcile.py::test_a_hands_resolution_of_a_roles_thread_is_matched_to_the_act_the_last_pass_named`, `controller/reconcile.py`, `tools/mutants.py`, mutant: "a hand's resolution no act named is matched", mutant: "any act names the thread a hand resolved", mutant: "another item's act names the thread a hand resolved", mutant: "an earlier pass names the thread though the last did not" |
| A matched thread is carried, stamped again while it is seen and kept for the window; one nobody named is not carried | `tests/test_reconcile.py::test_a_hands_resolution_once_matched_is_carried_while_it_is_seen`, `controller/reconcile.py`, `schemas/pass.schema.json`, `tools/mutants.py`, mutant: "a matched hand's resolution is not carried", mutant: "a carried hand's resolution outlasts the window" |
| One no record before can judge leaves reconciliation short for that pass, and is carried | `tests/test_reconcile.py::test_a_hands_resolution_no_record_can_judge_is_short_once_and_carried`, `controller/reconcile.py`, `tools/mutants.py`, mutant: "a hand's resolution no record can judge is silent", mutant: "a hand's resolution no record can judge alarms" |
