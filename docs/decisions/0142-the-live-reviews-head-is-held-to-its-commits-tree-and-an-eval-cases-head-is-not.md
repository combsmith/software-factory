# 0142. The live review's head is held to its commit's tree, and an eval case's head is not

Status: accepted. The Factory Builder's ruling of 2026-11-04 on issue 543, "The review's head is held to the commit's tree, file by file, by its blob hash", option (a), from `trials/P-60.tree.json`. It adds to decision 0138's row "The head, for a live Run" a check of the head against its commit's tree, and leaves its rows "A transport with no token" and "The eval case" as they are. Nothing else in 0138 changes.

## Decision

| What | Decided | Because |
|---|---|---|
| The tree, for a live Run | `harness/read.py` reads the commit's tree beside its tarball, with the same reader token and the same grant, `read:task.change` (contents: read), as `GET /repos/{home}/git/trees/{sha}?recursive=1` of the head the diff was read at. It is refused unless answered 200, with `truncated` false, each entry once and each of a kind the check reads: a folder, a regular file (100644 or 100755) with its blob hash and size, or a link (120000). A submodule or any other entry refuses it. A tree refused stops the read step, `head_unreadable`, and no Task is built | P-60's tree read: the API answered the canary commit's tree 200, not truncated, with each file's mode, size and blob hash, and a commit it does not hold 422. A tree that is not whole cannot show that nothing was left out |
| The head held to it | Once unpacked, every regular file the tree lists is a file in the head, whose git blob hash, sha1 of `blob <size>\0` and its bytes, and size are the tree's, and no file is there that the tree lacks. A link is left out by the unpacker and is not looked for; one found in the head, to a file or a folder, refuses it. A head that differs in any file stops the read step, `head_unreadable`, and leaves nothing a run could take for a Task | GitHub builds the archive with git archive, which reads the commit's own `.gitattributes`: a file marked `export-ignore` is not in the archive, and one marked `export-subst` is not as committed. A pull request can add such a line. All 22 of P-60's files matched their blob hashes, so a head built as codeload serves it passes |
| An eval case's head | Not held to its tree. The eval's fetch, `harness/eval/fetch.py`, reads each case's tarball with no credential as before, and a transport with no token still sends a commit's tarball alone, never a tree | The cases are pinned commits chosen for the held-out set, not a stranger's pull request. The anonymous cap is 60 calls an hour, and the tarballs already take 40 of them, so a tree read for each case would pass it. The eval's path stays the one the replay measured |
| The cost | An eval case is graded on its tarball, and the live review on the checked tree. A case whose `.gitattributes` changes its archive could be judged on files the live review would refuse, so the gate would pass a reading the Factory never gives live. And git archive applies more of a commit's `.gitattributes` than `export-ignore` and `export-subst`: `ident`, `eol` or `text`, and `working-tree-encoding` rewrite a file's bytes too. A repo with such a line, as common as `*.bat eol=crlf`, gets `head_unreadable` on every live review of a commit that holds it, and no review | Named so that it is not mistaken for a guarantee, nor the second found later as a bug. Whether any case chosen carries such a line is not checked. This repo has no `.gitattributes`; the check fails closed, and a Consumer's repo with one waits on reading the head another way |
| Later | Reading the eval's trees with the home's token, or throttling the eval's anonymous reads to fit them, is later work, with no issue opened | Neither is needed while the cases are chosen by hand |

## Why

Decision 0138 gave the review the pull request's head and told the model that the archive is not quite the commit, but nothing checked it, so a pull request could hide a file from the review, or show it other bytes, with one line of `.gitattributes`. The diff shows that line, but a model may miss it. Reading the commit's tree costs one more read with a token the step already holds, and a blob hash per file says whether the head is the commit, byte for byte. The eval is left as it is, by the anonymous cap and because its commits are chosen, and the gap that leaves is named rather than closed.

## Boundaries

| Boundary | Check |
|---|---|
| P-60's head is held to its commit's tree as the API answered it whole (`trials/P-60.tree.json`), and a commit not held is no tree; a byte changed, a byte more, a file gone, a file more, a link planted, to a file or a folder, or a size not the file's is refused; a tree is asked by the commit's whole sha alone, of a repo named as the API names one | `tests/test_harness.py::test_the_head_of_p60_is_held_to_its_commits_tree` |
| A tree not answered 200 and whole, or holding a submodule, a path twice, or an entry of a kind or mode the check does not read, is refused; links are kept apart | `tests/test_harness.py::test_a_tree_not_answered_whole_or_holding_what_an_archive_cannot_is_refused` |
| The reader reads the tree at the head the diff was read at, with its token; a tree refused, or a head not its tree, stops it and leaves nothing | `tests/test_steps.py::test_the_reader_writes_the_tasks_inputs`, `tests/test_steps.py::test_a_head_that_cannot_be_read_or_unpacked_whole_builds_no_task` |
| A transport with no token sends no tree read | `tests/test_adapters.py::test_a_transport_with_no_token_sends_a_commits_tarball_alone` |
| Each of these rules has a mutant that a test kills | `tools/mutants.py` |
