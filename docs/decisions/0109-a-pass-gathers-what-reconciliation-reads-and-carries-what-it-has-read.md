# 0109. A pass gathers what reconciliation reads, and carries what it has read

Status: accepted. The Factory Builder's rulings of 2026-10-31 on wiring the live pass, an item of the audit of "Epic: slice 1, first approval. A Release on next reviews a pull request to this repo, and the machine user's approval stands" (issue 182). It builds what `docs/decisions/0061-every-write-a-factory-identity-makes-is-matched-to-a-recorded-effect-and-one-that-is-not-raises-one-alert.md` left waiting on the pass's entry, and adds to it how a Run is read once.

## Decision

| What | Decided | Because |
|---|---|---|
| What the entry gathers | `controller/__main__.py` hands each snapshot a `kept`, and hands what it kept to `adapters/seen.py` for each open pull request, with each one the last record served, or could not read, that has left, read as left, and the machine user's pushes. A pull request read short is owed, in the record, and read again until it has been, so that one closing after a short read is not lost. With no records before it to say what has left, what it saw is short. It reads each snapshot's first answer for its date and age, as `facts_reads`. The window is a day and `not_run_seconds` back from the read | Every live pass read short before this, and raised `reconciliation_unreadable` |
| What it reads of what was recorded | Each completed Run the records port lists in the window has its `applied/1` read (`adapters/applied.py`'s `effects`), and each completed pass of the poller its `written/1` (`adapters/passes.py`'s `written`), held to its schema and to a record's bound. One that succeeded and lists none, or whose record cannot be read, is not counted read, so a later pass reads it again, and reconciliation is short until then. One that failed and lists none may be yet to, so it too is read again, without being short. A list that counts differently between pages, or names a pass twice, is short, and a pass is read once. Only the approving act's record vouches for an approval | A record any job could upload could cover a stolen credential's write, so only a listed Run is read (0061), and a Role's Run cannot speak for the machine user |
| Read once | `pass/1` gains `reconciled`: the Runs and each pass's attempt read, since a re-run writes again, each stamped with when it was read; each Effect's key, each write matched by its item with its count, and each dispatch, each stamped with when its record was made, so a late first read does not stretch its credit; and what is owed. Each is dropped once older than the window. Reconciliation matches what this pass read and what the last record carried. A last record that cannot be read, or holds none, reads everything in the window again | 0061 says each is read once and its keys kept. A record keeps what the Effects said, not the records. Read each pass, a window of thirty hours costs about two reads for every pass and Run in it. It changes `pass/1`, never `facts/1`, so no held-out case moves |
| How much a pass reads | At most fifty Runs and fifty passes, newest first, so that a pass that knows nothing stays inside its step's six minutes (decision 0098). The rest is short, and the next passes read on from what the record says it read. Ten pages of a hundred bound the list; past them what was listed is still read, and it is short | A step killed at its limit leaves no record, and a pass that cannot finish would never catch up |
| Writes still being recorded | A write by a Role or the machine user on an item with a Run still running reads as short, not as unmatched, since a Run writes before it uploads its record. The Controller's own writes do not wait | An alert asks the Maintainer to rotate a credential, so an ordinary Run must not raise it |
| What does not fit | A landed Effect's key or item too wide for `pass/1` is not carried, and reconciliation is short: one record never refuses a pass | `applied/1` and `written/1` are wider than what a pass record carries, and a refused pass raises no alert at all |
| The accounts | `accounts.controller` and `roles.pr-review` are set to the bot accounts GitHub's users API answers, each with its login, id and type, recorded in `trials/P-39.accounts.json`. `tools/check_trials.py` lets the org's fixture read a Factory App's bot account by the one form its login takes, and no other account | Reconciliation is short while any writing identity's account is not known (0061), so the Controller's alone would not do |
| What setting them turns on | Tracking-issue writes (decision 0060), which wait on `accounts.controller`, and the Controller's acts are read as the Factory's. Nothing runs until the workflow that calls the pass exists | The Factory Builder's ruling |
| The comments read | `pull_requests: read` serves a pull request's comments, as trial P-56 answered: 200, and the header names `issues=read; pull_requests=read`. Were GitHub to refuse it, every pass raises `reconciliation_unreadable`, which is loud and admits nothing wrongly | The Factory Builder's ruling was to build regardless; the trial then settled it |

## Why

Reconciliation was built and tested and nothing fed it, so the one alert that says a Factory identity wrote what it did not record could only ever say it could not read. This feeds it, at a cost that does not grow with the window.

## Boundaries

| Boundary | Check |
|---|---|
| The entry hands each snapshot's `kept` to the seen port, each item once, reads one that left as left, reads the pushes, and reads each facts read's date and age; what it cannot read is short, and fails no pass | `tests/test_controller.py::test_the_entry_gathers_what_reconciliation_reads` |
| A pass's attempt in the window is read once; one that succeeded and lists none, or cannot be read, is short and read again; one that failed and lists none is read again; a list that cannot be read, runs past its pages, counts differently or names one twice, is not whole; a pass reads at most its limit | `tests/test_adapters.py::test_each_pass_in_the_window_is_read_once_and_what_cannot_be_read_is_read_again` |
| A listed Run in the window is read once; one running or older is not; one whose record cannot be read is read again; a list not whole reads nothing; only the approving act's record vouches for an approval; a pass reads at most its limit | `tests/test_adapters.py::test_each_run_in_the_window_is_read_once_and_only_a_listed_one` |
| What a pass read matches a write in the passes after it, for the window, a dequeue as many times as it was recorded | `tests/test_reconcile.py::test_what_a_pass_read_matches_a_write_in_the_passes_after_it_for_the_window` |
| What is older than the window is dropped, and matches nothing | `tests/test_reconcile.py::test_what_is_older_than_the_window_is_dropped_and_matches_nothing` |
| A record that holds none reads everything again; what cannot be read carries on what was held; `reconciled` is held to its shape | `tests/test_reconcile.py::test_a_record_that_holds_none_is_read_again_and_what_cannot_be_read_is_carried_on` |
| A record too wide for the pass record is not carried, is short, and refuses nothing | `tests/test_reconcile.py::test_a_record_too_wide_for_the_pass_record_leaves_it_short_and_never_refuses_a_pass` |
| A write on an item with a Run still running is short, not unmatched; any other, the Controller's among them, is matched as ever | `tests/test_reconcile.py::test_a_run_still_running_makes_its_items_writes_short_not_unmatched` |
| The accounts are what GitHub answered, and known | `tests/test_reconcile.py::test_each_identity_is_told_by_its_account_from_the_configuration` |
| A Factory App's bot account alone is the org's fixture's to read | `tests/test_tools.py::test_a_fixture_of_the_org_asks_by_rest_of_this_org_alone_and_climbs_nowhere` |
| The workflow that calls the pass runs it | waiting on `.github/workflows/poller.yml` |
| Each of these rules has a mutant that a test kills | `tools/mutants.py` |
