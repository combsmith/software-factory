# 0237. A commit closer is read only as a listed pull request's merge, and the closers' rows say what the port reads and the trials it still owes

Status: accepted. Replaces `docs/decisions/0174-two-pull-requests-linked-by-hand-before-an-issues-merge-leave-it-held-and-its-type-changes-are-read-whole.md` and `docs/decisions/0218-an-issues-timeline-is-read-by-rest-whole-by-its-missing-next-link-and-an-apps-act-with-a-persons-token-is-the-apps.md`. The Factory Builder's rulings on "A commit closer's merge-sha match is not held, a closer of no type reads as none, and the closers' row says more than the code" (issue 971): the closers' row that decisions 0028, 0139 and 0141 each carry, whose Boundary cell is fixed, says more than the port does, so a new record states the closers as the port reads them. It keeps all of 0174 but that, the words of 0141's row on a linked draft's flag at a time, and those of the row on the default branch's pull requests that the three decisions carry, which reads the join as the port does not, item 6 of "The closing part's query arguments, default branch, first close and short-read memory are not held, and 0141's flag row names a function nothing calls" (issue 970), and decides nothing the code does not already do. Of 0218 it keeps all but its row "While the keyword spans are not read", which since "The issues port builds keyword spans from pass records" (issue 734) no longer holds, and its Owed row, which trial P-72 settles.

## Decision

| What | Decided | Because |
|---|---|---|
| A pull request's close | The port reads each close in the issue's timeline, read beside `closed_first_at`, and names a pull request its closer by repository and number alone, as the closer gives them. It lists as linked, while its base is the default branch, each pull request the timeline names the closer of a close in the present life, whatever its references say now; a pull request's first close in the present life is its `closed_issue_at`, and only where it made none in this life its first of all. A closer of the present life to another base leaves the list not whole | References can change after the merge (`trials/P-46.json`). | A commit closer | A closer of type `Commit` names no pull request and lists none. It counts only as the merge commit, matched by its whole id, of one merged pull request already listed, by its reference, a link by hand, a close it made or a keyword a pass saw; it then gives that pull request its `closed_issue_at`, unless the pull request made an earlier close in the present life. A commit closer of the present life that no listed pull request merged leaves the list not whole, and the issue defers: a listed one merged by another commit, not merged, or closed without a merge is no match. One of the present life with no id, or an id that is no string, refuses the read. | Other closers, and lives before | A pull request of another repo, or a closer of another kind, of the present life leaves the list not whole. Of a life before, each of these and a commit closer, whatever its id and whether or not a listed pull request merged it, is passed over and credits no close, its id never read, and still names the issue where the pass records break the chain of spans (the row "The keyword spans" below); a close in the second the present life began is of the present life. A closer that names no type, or whose type is no name, refuses the read, in any life; a person's close names no closer, and names nothing | A closer of a life before moves nothing in the present life, which began at a writer's reopening; refusing on it would stall the issue for good on a close no one can change, item 6 of the issue the Status names. ## Why

The closers' row came down from decision 0028 through 0139 and 0141, and its Boundary cell is fixed: it still names a pull request the closer by its merge commit, whatever its references say, and owes a trial of the queue's squash first. The code credits a commit closer only to a listed pull request it merged, holds the list not whole where none did, passes over a closer of a life before, and the squash's trial is recorded. Rows added beside the old one said so in their Check cells; a reader of the Boundary alone still met two answers. The row on the default branch's pull requests, carried the same way, reads the join from each pull request's own references alone, which the port never did. This record gives one answer for each.
