# 0237. A commit closer is read only as a listed pull request's merge, and the closers' rows say what the port reads and the trials it still owes

Status: accepted. Replaces `docs/decisions/0174-two-pull-requests-linked-by-hand-before-an-issues-merge-leave-it-held-and-its-type-changes-are-read-whole.md`. The Factory Builder's ruling on "A commit closer's merge-sha match is not held, a closer of no type reads as none, and the closers' row says more than the code" (issue 971): the closers' row that decisions 0028, 0139 and 0141 each carry, whose Boundary cell is fixed, says more than the port does, so a new record states the closers as the port reads them. It keeps all of 0174 but that, and the words of 0141's row on a linked draft's flag at a time, and decides nothing the code does not already do.

## Decision

| What | Decided | Because |
|---|---|---|
| A pull request's close | The port reads each close in the issue's timeline, read beside `closed_first_at`, and names a pull request its closer by repository and number alone, as the closer gives them. It lists as linked, while its base is the default branch, each pull request the timeline names the closer of a close in the present life, whatever its references say now; a pull request's first close in the present life is its `closed_issue_at`, and only where it made none in this life its first of all. A closer of the present life to another base leaves the list not whole | References can change after the merge (`trials/P-46.json`). A merge commit's close names its pull request by repository and number (`trials/P-33.json`), and so does the queue's squash (`trials/P-67.json`) |
| A commit closer | A closer of type `Commit` names no pull request and lists none. It counts only as the merge commit, matched by its whole id, of one merged pull request already listed, by its reference, a link by hand, a close it made or a keyword a pass saw; it then gives that pull request its `closed_issue_at`, unless the pull request made an earlier close in the present life. A commit closer of the present life that no listed pull request merged leaves the list not whole, and the issue defers: a listed one merged by another commit, not merged, or closed without a merge is no match. One of the present life with no id, or an id that is no string, refuses the read. A linked pull request closed without a merge reads no `merged_at`, so no commit closer is matched to it | A commit pushed to the default branch with a closing keyword in its message closes the issue with no pull request merged: listing a pull request by it would credit a merge that closed nothing, and reading the list whole would hide a close the facts do not carry |
| Other closers, and lives before | A pull request of another repo, or a closer of another kind, of the present life leaves the list not whole. Of a life before, each of these and a commit closer, whatever its id and whether or not a listed pull request merged it, is passed over and credits no close, its id never read, and still names the issue where the pass records break the chain of spans (decision 0218); a close in the second the present life began is of the present life. A closer that names no type, or whose type is no name, refuses the read, in any life; a person's close names no closer, and names nothing | A closer of a life before moves nothing in the present life, which began at a writer's reopening; refusing on it would stall the issue for good on a close no one can change, item 6 of the issue the Status names. A closer of no type is a read that failed, never a person's close |
| The trials | The queue's squash's closer is recorded (`trials/P-67.json`), read in `tests/test_adapters.py::test_the_queues_squash_and_a_link_by_hand_are_read_as_their_trials_recorded_them`, and is owed no more. No recorded answer holds a closer of type `Commit`, so its reading is the port's alone, held by its tests and mutants: a trial of a push that closes an issue by a commit's message is owed. So is a trial of an edit that takes out a reference that stood at the merge, which "Trial: a cross-referenced event survives an edit that takes the closing keyword out, a commit's keyword leaves a referenced event, and what a hidden author's pull request shows" (issue 990) takes up | The closers' row of decisions 0028, 0139 and 0141 still calls the squash's trial owed first, and names a closer by its merge commit as if a trial grounded it |
| How the flag reads at a time | As record 0174 words it. Its reading is the port's, `linked.draft_at`, alone, which nothing but its test calls, since the Kernel may import no adapter (`tools/check_purity.py`). Until a link's time can be proven, row 1 reads no linked pull request's flag at the merge, as it stood or as it stands; the day it does, its own reading in `kernel/issue.py` takes a boundary test and mutants of its own | Decision 0141's row on the flag at a time says row 1 reads it, with its labels, once a link's time can be proven, and named the port's test and mutants as if they held row 1 |
| What stays | Everything else record 0174 decides, as it words it, as decision 0186 amends it and decision 0183 adds to it, and with it record 0141, decisions 0139, 0028 and 0132 as 0174 keeps them, and decision 0218's amendment of their timeline's row; and 0174's Boundaries, and 0141's as 0174 keeps them, each held by the check it names there, but the closers' row and 0141's row on the flag at a time, whose words the rows below state as the port reads them | Only words change: the code already reads the closers and the flag as this record says |

## Why

The closers' row came down from decision 0028 through 0139 and 0141, and its Boundary cell is fixed: it still names a pull request the closer by its merge commit, whatever its references say, and owes a trial of the queue's squash first. The code credits a commit closer only to a listed pull request it merged, holds the list not whole where none did, passes over a closer of a life before, and the squash's trial is recorded. Rows added beside the old one said so in their Check cells; a reader of the Boundary alone still met two answers. This record gives one.
