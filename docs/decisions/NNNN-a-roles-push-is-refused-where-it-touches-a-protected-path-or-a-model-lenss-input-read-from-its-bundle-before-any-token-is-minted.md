# NNNN. A Role's push is refused where it touches a protected path or a model Lens's input, read from its bundle before any token is minted

Status: accepted. Replaces `docs/decisions/0070-a-roles-push-that-touches-the-bases-list-is-refused.md`. Taken on the Factory Builder's rulings of 2026-11-10 for "Harness: apply refuses a Role's push to a protected path or a Lens's input that no model Lens has reviewed" (issue 139), which the Maintainer may overturn in review. It keeps 0070's reading of the list and its refusal, narrows what the refusal holds, and gives it its caller.

## Decision

| What | Decided | Because |
|---|---|---|
| What is refused | A Role's push that changes a path on the list, or renames or copies one out of it, is refused, `push_protected`, the Role's fault. The list is every protected path of `config/hooks.json`, and each input of a model Lens that `config/defaults.json` names. That covers the Lifecycle, the authority table, the gate, the brakes, `.github/`, the code owners wherever GitHub reads them, and the hooks (records 0004 and 0005), and every model Lens's own input (record 0052). A path that cannot be read as one, or paths that are no list, are refused too, as 0070 had it | These are what a person must judge, and what judges a change. Such a change is a person's to push |
| What is pushed | A path that is only a deterministic Lens's input, `verify`'s or the secret scan's, or on no list at all, is pushed. Record 0020 then holds its pull request at convergence until every model Lens has reviewed its head | The Maintainer's own ruling in 0020 is that a Role's change to a Lens's inputs needs a model review, not a person. Under 0070 the list held every Lens's input, `kernel/`, `tools/`, `tests/` and every file at the top of the repo among them, so the Factory's author could push nothing but `docs/` to its own repo |
| The list | `config/hooks.json` and `config/defaults.json` as the pull request's base commit holds them, read by `adapters/rules.py` through the token `apply` reads with, at the base sha from the trusted read of the pull request, as 0070 read the first. The model Lenses are the ones that commit's `config/defaults.json` names. A file that cannot be read, or a commit that names no model Lens, is `push_list_unreadable`, the Factory's | A change cannot take itself off the list, nor turn a model Lens into a deterministic one. With no model Lens, nothing would review what this lets through |
| The code owners | The code owners file at the top of the repo, `CODEOWNERS`, and the one under `docs`, join `.github/` among the protected paths | GitHub reads the code owners from any of the three. Under 0070 the top-level `*` of `verify`'s inputs refused the first; under this record nothing else would |
| The push Effect | `effect/1` gains `push_commits`, one to a Result. It names the bundle its Run handed over, by the artifact and the digest. The branch it lands on and the commit it lands on top of are `apply`'s, never the Result's. No Role permits it yet | `apply` decides where a write lands, as it does for a review's commit |
| The bundle | A patch as `git diff` writes it. `harness/bundle.py`'s `fetch_bundle(artifact, digest)` fetches it; how a Run hands a bundle over is for issue 314, "Design: a Run with tools cannot both hide the model credential and hold writes", to choose, and until then that function fetches nothing. The bundle is taken only by its digest. Every name it writes or reads is read from the patch itself, never from the Result: a section's header, a rename's or a copy's two names, and both sides of its hunks, which must name what the header or the rename names. Each name is read as git reads it, a quoted one unquoted byte by byte. A line that reading does not know, a hunk whose lines are not the count its header gives, or a count of more than nine digits makes the bundle unreadable, `bundle_unreadable`. So does a name git would read otherwise: an unquoted name that holds a double quote, a backslash or a control character, text after a quoted name, or `/dev/null` with no mode line that makes or removes the file. So does a line led by a backslash that is not git's own marker for a file with no newline at its end. So does a binary change, as a binary patch or as a line that holds a NUL | Every shape issue 314's proposal weighs hands `apply` a bundle by artifact and digest. Reading the names from the bundle means a Result cannot describe one change and hand over another. A binary change has no hunk a person can read, so it is a person's to push |
| Where it is called | `apply.job` holds a push after every other check and before it mints any token, through `held`, which the step gives it. `harness/apply_step.py` binds `harness/bundle.py`'s `held` to the read token and the base commit of a read of the pull request at the head its facts were read at; a pull request that moved since is a change under the Run. `held` reads the list first, then fetches, checks the digest, reads the names and calls `push_refusal`. A Result that asks for a push when no `held` is given is refused, `push_not_held`. A refusal lists each Effect the Result asked for as refused, with its reason, in `applied/1`, and gives its fault and code in `outcome/1` | Nothing is written and nothing is minted for a push that may not land |
| Whose fault | `push_protected`, `bundle_unreadable`, `bundle_digest_differs` and `bundle_not_handed_over` (an artifact this Run did not hand over) are the Role's. `push_list_unreadable`, `bundle_unfetched` (a fetch that failed) and `push_not_held` are the Factory's | The Result names the bundle, so no item can pause the Factory through what its Run hands over or names |
| What waits | The push's write itself, which lands the bundle's commits on the work branch, comes with the fix Intent's push. So does the fetch, by the choice the bundle's row names. Until both exist, a push this lets through is refused by the token's grant: `config/apps.json` names no need for `push_commits` | This record holds what a push may touch, not how it lands |
| Residual: the author may change what `verify` reads | A Role may push a change to `kernel/`, `tools/`, `tests/`, `schemas/` and the other inputs of a deterministic Lens, and to the secret scan's configuration. Such a change is held only by every model Lens's review and the machine user's approval at convergence. Issue 198, "The ruleset switch: main requires the machine user's approval of the most recent commit, and slice 1's event is recorded", makes that approval required | Written down, as the Factory Builder asked. A person still approves any change to a model Lens's own input (0052) |
| Residual: the names are the patch's | What is checked is the names the patch carries. The push's write must land exactly that patch, and no other bytes. That is its to hold when it comes | Written down, so that the write's story holds it |

## Why

Decision 0070 read "no model Lens has reviewed" as "touches the list", and its list held every Lens's input. Decision
0020 holds such a change at convergence, until every model Lens has reviewed its head, and 0052 adds a person for a
model Lens's own inputs. Refusing at the push what a person must judge or what a model Lens is given keeps both, and
leaves the rest to the review 0020 already requires. It lets the Factory's author write its own code (design section 9.1,
slice 2).

| Boundary | Check |
|---|---|

| The list is the base commit's protected paths and its model Lenses' inputs, each once, never a deterministic Lens's alone, the model Lenses read at that commit | `tests/test_adapters.py::test_the_list_is_the_bases_every_protected_path_and_model_lens_input_once`, `adapters/rules.py`, `tools/hooks/protected.py`; mutant: "a deterministic Lens's input is refused at a push"; mutant: "the base's model Lenses are not read"; mutant: "a model Lens's inputs are pushed" |
| A commit that names no model Lens, or whose config/defaults.json cannot be read, refuses every push as unreadable | `tests/test_adapters.py::test_a_commit_that_names_no_model_lens_is_unreadable`, `adapters/rules.py`; mutant: "a commit that names no model Lens is read" |
| The list is read first, at the base, and one that cannot be read refuses the push, the Factory's, with no bundle fetched | `tests/test_apply.py::test_the_list_is_the_bases_read_first_and_unread_refuses_every_push`, `harness/bundle.py`; mutant: "a bundle is fetched though the list is unread"; mutant: "the list is read at another commit than the base"; mutant: "an unreadable list the refusal reads is the Role's" |
| A bundle is taken only by its digest; one not fetched is the Factory's, one the Run did not hand over the Role's | `tests/test_apply.py::test_a_bundle_is_taken_only_by_its_digest_and_read_from_itself`, `harness/bundle.py`; mutant: "a push's bundle is taken by any digest"; mutant: "a bundle not fetched is the Role's"; mutant: "a bundle the Run did not hand over is the Factory's" |
| Every name a patch writes or reads is read from it: its header, a rename's and a copy's lines, its sides, a quoted name | `tests/test_apply.py::test_every_name_a_patch_writes_or_reads_is_read_from_it`, `tests/test_apply.py::test_a_patch_as_git_writes_it_is_read_whole`, `harness/bundle.py`; mutant: "a push's rename and copy lines are not read"; mutant: "a push's header names are not read"; mutant: "a header of a name with a space is not read"; mutant: "a quoted name is read with its quotes"; mutant: "a hunk with no count is read as none" |
| What is not a patch of text is unreadable: a line before its first section, a hunk cut short or of a count past nine digits, a name past UTF-8, a side named with neither of git's two prefixes, a name git would read otherwise, a side that names what its header does not or has another prefix, `/dev/null` with no mode line, a marker git does not write, a line with a NUL, a binary change | `tests/test_apply.py::test_what_is_not_a_patch_of_text_is_unreadable`, `harness/bundle.py`; mutant: "a line before a push's section is passed over"; mutant: "a hunk cut short is read"; mutant: "a name past UTF-8 is read"; mutant: "an unquoted name that holds a quote is read"; mutant: "text after a quoted name is read"; mutant: "an escape git does not write is read"; mutant: "/dev/null is read as no file without its mode line"; mutant: "a side that names what its header does not is read"; mutant: "a hunk count of ten digits is read"; mutant: "a side of no a/ or b/ is read"; mutant: "a line with a NUL is read"; mutant: "any line led by a backslash is read as git's marker" |
| `apply` holds a push after every other check and before it mints; a push with no hold is refused; a refusal lists each Effect refused, the push first; a push lands on the commit the Decision admitted, and names no branch; one push to a Result | `tests/test_apply.py::test_a_push_is_held_before_anything_is_minted_and_its_refusal_recorded`, `harness/apply.py`, `schemas/effect.schema.json`, `examples/invalid/effect.a-push-that-names-its-branch.json`; mutant: "a push is never held"; mutant: "a push with no hold lands"; mutant: "a refused push is not recorded"; mutant: "a push names no commit it lands on"; mutant: "a Result may push twice" |
