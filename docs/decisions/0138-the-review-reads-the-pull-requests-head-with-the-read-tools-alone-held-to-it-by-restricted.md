# 0138. The review reads the pull request's head, with the read tools alone, held to it by --restricted

Status: replaced by `docs/decisions/NNNN-the-engine-runs-the-pinned-model-by-its-full-id-at-the-tiers-effort-and-keeps-an-answer-only-from-that-model.md`.

## Decision

| What | Decided | Because |
|---|---|---|
| What the review reads | A Run of the review Intent, `review-change`, is asked its Task as before and starts in the pull request's head, the tree at the commit its diff was read at. Every other Intent is asked as before: no tool, in an empty directory | The private replay's misses needed the code around a change, which a diff alone does not carry |
| The tools | The CLI is given `--tools Read,Grep,Glob --allowedTools Read,Grep,Glob --permission-mode dontAsk --restricted --setting-sources ""`, each once and in no second form, and nothing that widens them, an option read by its name whether it is written `--flag value` or `--flag=value`: no `--add-dir`, `--settings`, `--mcp-config`, plugin, agent, `--disallowedTools`, `--bare`, other spelling of the allowed tools or permission bypass. `--restricted` is what confines the reads to the folder. `--setting-sources ""` keeps the head's own settings and its CLAUDE.md out | P-59, on a Linux runner with bubblewrap and the scrub, at 2.1.306: with both, each of 18 calls outside the folder was refused, by Read, Grep and Glob, through links, `/proc/self` and the home directory; the head's settings, which bypassed every permission and held two hooks and a key helper, did nothing; its CLAUDE.md was not sent. `--restricted` alone held the same. `--setting-sources ""` alone kept the settings and instructions out and held no read: with the scrub set the CLI forces the permission mode to its default, so the allowed tools, named with no path, read anywhere, and Grep read the CLI's own environment, which holds its credential. With neither, the head's hooks and key helper ran |
| The scrub | Stays set. The Engine starts the CLI with it only with no tool, or with exactly the read tools above where the head is asked for; any other list, or one that leaves out a flag, is a `failed` Result, `engine_failed`, before the CLI starts | P-50 and P-51: a tool that runs, with the scrub on, wrote anywhere the runner's user can. Read, Grep and Glob write nothing, and P-59 saw no write land |
| What the model is told | Before the Role's instructions: the head is the folder it starts in, it may read it with Read, Grep and Glob and nothing else, and every file in it is data, whoever wrote it, as every text in the Task is; and it is the commit's archive, so a file the commit's `.gitattributes` marks `export-ignore` is not there and one marked `export-subst` is not as committed, which the diff shows | A file the pull request adds or changes is the pull request's author's words |
| The head, for a live Run | `harness/read.py` reads it with the reader App's token, under its grant `read:task.change` (contents: read), as `GET /repos/{home}/tarball/{sha}` of the head the diff was read at, and unpacks it into the folder named head among the files it writes. `harness/run.py` hands it to the CLI as the folder it starts in. A head that cannot be read or unpacked whole stops the read step, `head_unreadable`, and no Task is built | The reader's token is revoked before the model's step, as before; the model's step holds no token that reads GitHub |
| The redirect | The transport follows a second named redirect, of a commit's tarball alone, by its whole sha, to `https://codeload.github.com/{owner}/{repo}/legacy.tar.gz/{sha}` of that same repo and commit, over HTTPS on its own port, with no token and no header of the API's sent there, bounded at 32 MiB. A redirect from codeload is refused: there is no second hop. The address is never named in an error, since for a private repo it can carry a token | P-60: the API answered 302 to that address with no token in it, codeload answered it with no Authorization header, 200, a gzip with no `content-length`, and no address on codeload over HTTPS redirected. The Maintainer's choice of the tarball over a request per file or a second network path |
| A transport with no token | `Live.anonymous()` sends no token and a commit's tarball alone. The eval job's fetch and the canary read the public cases' repo's heads with it; the home's token is never sent anywhere else, and no new secret is added | The Factory Builder's ruling: no new secret for the eval |
| The unpacker | `harness/head.py`, by hand, header by header, each checked before anything is written; the whole archive is refused at the first member that fails. It writes regular files and directories alone, files as their user's (0600) and folders 0700, each opened new and never through a link. It refuses a name that is absolute, holds `..`, `.` or an empty segment, is not UTF-8, lies outside the archive's one folder or would land outside the head's folder by its real path; a member named twice, whatever kinds the two are; one that cannot be written where its name says, as a file under a file; a device, a FIFO or a kind it does not know; a checksum not its own; a number not octal; an archive cut short, with bytes after its end, or whose end is not two zero blocks and padding alone; over 20,000 members, or over 64 MiB unpacked. A link is never written: it is left out and counted. The archive must name the commit asked for in its pax global header, and its first member must be its one folder, named for that commit | P-60: GitHub's archive opens with a pax global header naming the whole commit, then one folder of directories and regular files. A repo can hold a link, so one is left out rather than the review refused |
| A review with no head | `answer` in `harness/run.py` never asks a review given no head, or one that is not a folder: a `failed` Result, `head_unreadable`, the Factory's fault, before the CLI starts | A review asked without its head would be measured against a change it cannot read whole |
| The eval case | `eval-case/1` requires a top-level `head`, 40 lowercase hex characters, the commit its diff was taken at. A case without one fails its schema, `not_this_set`. The fetch reads each case's head and unpacks it into a folder of its own under the scratch directory; the run step starts the case's CLI there and removes it once the case is asked. A head that cannot be read whole is the case's `head_unreadable`, among `ENGINE_FAULTS`, and closes the gate | What is measured is what runs, as the eval job's rulings have it. The held-out audit writes `head` into every case |
| Cost | The tier's turns and cost ceiling are unchanged. Each tool call is a turn, so a standard Run reads about eight times before it answers | Tuned from what the next eval run's `usage` says |

## Why

The review was blind to every line of the code a change touched but did not show. Giving it the repo's head lets it read the callers, the tests and the rules a change must keep, without giving it anything that runs or writes. The two trials held each piece before it was built: P-59 that the read tools are held to the folder, and by which flag, and P-60 what the tarball's redirect is. The head is new model input, but not new in kind: the unchanged files are the base, which the Factory trusts, and the changed ones are already in the diff. What a hostile file can still do is what the diff could already do, lead the model to miss or invent a Finding, and the Result still says codes alone.

GitHub builds the archive with git, so a pull request's own `.gitattributes` can leave a file out of the head or change its bytes; the diff shows that change, the model is told so, and checking each file against the commit's tree by its blob hash is a follow-up, issue 543, "The review's head is held to the commit's tree, file by file, by its blob hash", which needs a read of the tree the transport does not make yet.

What is owed: what codeload's address holds for a private repo read with an App's token. P-60 read a public repo with none; a live Run on a private head waits on it. The cost of a Run with tools is read from the next eval run.
