# NNNN. A case's head is read from the held-out home, pinned by the case, and held to its tree

Status: accepted. The Factory Builder's rulings of 2026-11-08 on issue 611, "A case's head is read from the private home, pinned by its hash, and the run is sharded", points (a) to (d): this is the first of its two pull requests, the heads; the second shards the run. It amends decision 0138's rows "A transport with no token" and "The eval case" where they say the eval job reads a case's head with no credential, and its Boundaries row "Each case's head is read with no credential and removed once asked", whose check is now the test of the read from the home; and decision 0142's row "An eval case's head", which this closes. Nothing else in either changes.

## Decision

| What | Decided | Because |
|---|---|---|
| Where a head is kept | Beside each case in the held-out home, `<role>/<id>.json`, the home keeps the case's head as two files: `<id>.tar.gz`, the commit's tarball as GitHub archived it, and `<id>.tree.json`, the commit's tree, every level of it, as the API answered it. `eval-case/1` requires `head_sha256` and `tree_sha256`, the sha256 of each, beside `head` | The issue's: a head read anonymously shares the anonymous cap, 60 an hour, so a pool of three runs, or a run again within the hour, can fault on `head_unreadable`; and a head that is not on GitHub cannot be read at all. Pinned by the case, which the manifest pins, the head is the bytes the Maintainer chose |
| How it is read | `fetch` reads both files with the home's token, through the transport the case is read with, by `beside` in `adapters/heldout.py`: each with the raw media type, `RAW` in `adapters/heldout.py`, whose answer is a file's bytes whole however large, in one answer and no redirect (`trials/P-62.json`). An answer of another type, `+json` among them, which the transport would read as JSON, is no file. A file over its bound (the transport's tarball bound, `TARRED`, or 8 MiB for a tree) is `too_large`, and one that does not hash to its pin `hash_differs`. Nothing in the eval job reads with no credential, and the home's token is still sent nowhere else | The Factory Builder's ruling (c): no transition, and no case without its pins, since an anonymous read kept for one would keep the read the issue removes. Ruling (d): the raw media type, grounded by its trial, the git blobs API its fallback; and the ruling on P-62's verdict, that the raw media type is GitHub's `vnd.github.raw`, which the transport must ask for |
| How it is held | The tarball is unpacked as before (decision 0138), and then held to the tree file by file, by git's blob hash, by the check a live head is held by (decision 0142): `tree_of` in `harness/head.py` reads the tree file with the checks `tree` reads GitHub's answer with, and `held` holds the head to it. A head not the one pinned is `hash_differs`, a fault of the run; one not read, unpacked or held whole is `head_unreadable`, the Engine's or the Factory's. Either closes the gate | The Factory Builder's ruling (b): pin the tree as well as the tarball, and hold every eval head to it. 0142 left an eval head unheld for want of room under the anonymous cap; read with the home's token, there is room. An eval case is now graded on the files a live review would be given |
| Who puts them there | The Maintainer, at his terminal, in his checkout of the home: `GH_TOKEN="$(gh auth token)" python3 -m tools.heads_into_home <home> <role folder>`. For each case of the folder, it reads the head's tarball and tree from GitHub through the one transport, read-only, holds the one to the other, writes both beside the case, the tree compact as GitHub's answer held it, and writes the case anew with their sha256 after its `head`; a case it cannot pin, or whose head is over what the job reads, it leaves as it was. Each file is written whole and moved over its name, so a link there is replaced, never written through, and a case or a folder that is a link is not read. It prints counts, then each pinned case's id and the sha256 of its new bytes, never a byte of a case. It takes a role folder and touches nothing else, so a gate set made later is pinned as the review Intent's set is | The Factory Builder's ruling (c): the tool serves the coming gate set too, and prints counts and hashes alone. A session never sees a case |
| The set changes with it | Pinning changes each case's bytes, so the set's manifest under `evals/` takes the hashes the tool prints, in the pull request that brings this change. It merges only once the home holds the files, and once `trials/P-62.json` is on main | The Factory Builder's ruling (c) and (d) |
| The canary | `harness/eval/canary.py` still reads its case's head with no credential: its case is this repo's own example, of this public repo, never one of the home's, and pins no file the home keeps | The canary is no step of the eval job (decision 0106) |
| Residual: a head only in the home | The tool reads a head from GitHub. A head that is not there, one built for a case, is written beside its case by hand, its tarball as `git archive` writes one with the commit in its pax header and one folder, and its tree in the API's shape; nothing builds that yet | No case of the set needs one yet. The eval reads it as it reads any other |
| Residual: the home's answer | P-62 asked a public repo. Should the API answer a private repo's file otherwise, a redirect among them, the read fails closed: the transport follows no redirect for a file, and a head not read whole is `head_unreadable` | Nothing the eval reads can be given in its place; the first dispatch after the Maintainer's run shows it |

## Why

A case's head was read with no credential, from the public repo its change was made in, which ties every run of the set to an hourly cap it shares with nothing else of the Factory's, and to GitHub keeping the commit. Kept in the home and pinned by the case, the head is read with the token every case is already read with, and is the same bytes on every run. The tree beside it lets the eval hold the head to the commit as the live review does, so a case can no longer be graded on files the live review would refuse.
