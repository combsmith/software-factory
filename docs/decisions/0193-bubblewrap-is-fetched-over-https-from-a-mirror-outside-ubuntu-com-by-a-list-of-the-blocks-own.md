# 0193. Bubblewrap is fetched over HTTPS from a mirror outside ubuntu.com, by a list of the block's own

Status: accepted. The Factory Builder's rulings of 2026-11-11 on "A Run's CLI install fails whole when the runner's Ubuntu mirror cannot be resolved" (issue 743), and on the reviewers' threads of the change that fixed it. It amends decision 0106's rows "The fix" and "The exception to 'nothing is installed'".

## Decision

| What | Decided | Because |
|---|---|---|
| The fault | On 2026-11-11 from 13:56Z, GitHub's `ubuntu-24.04` runners resolved no `ubuntu.com` or `launchpad.net` name, and each lookup stalled about 20 s. The image's apt reads `/etc/apt/apt-mirrors.txt`, a mirror list that tries `azure.archive.ubuntu.com` first for every file, so `apt-get update` ran past the install step's three minutes, and every review Run failed (run 43046213251). `archive.ubuntu.com` and `security.ubuntu.com` did not resolve either (the canary's run 43047814971); `mirrors.edge.kernel.org` did (its run 43048275193) | Read on real runners, as decision 0106's cause was |
| The fix | `CLI_INSTALL_RUN`, in `tools/check_workflows.py`, which holds `.github/workflows/eval.yml` and `.github/workflows/run-jobs.yml` word for word and the canary's install, writes `/tmp/ubuntu.list` with three sources, `https://mirrors.edge.kernel.org/ubuntu` for `noble`, `noble-updates` and `noble-security`, `main` alone, each `[signed-by=/usr/share/keyrings/ubuntu-archive-keyring.gpg]`; the first line starts the list and the others add to it. `apt-get update` and `apt-get install` each read that list alone, `-o Dir::Etc::sourcelist=/tmp/ubuntu.list -o Dir::Etc::sourceparts=-`, with `-o Acquire::Retries=2 -o Acquire::https::Timeout=10`. The image's mirror list, and every other source it names, is never read. There is no branching in the step | The canary's run 43101071038 installed bubblewrap 0.9.0-1ubuntu0.3 over this block in about 3 s. A fallback that tries the image's sources first spends the step's three minutes on stalled lookups before it falls back |
| The exception to "nothing is installed" | Still the one apt fetch here, the one package, unversioned, 50 kB; now over HTTPS from kernel.org's Ubuntu mirror in place of plain HTTP from the runner's Azure one. What holds it is still Ubuntu's signature on the index, and apt's refusal of a package whose hash the index does not give: the transport adds only that the mirror is the one named | Decision 0106's reasons stand; a third-party mirror changes who serves the bytes, not who signs them |
| What it holds and what it does not | Ubuntu's InRelease carries no `Valid-Until`, so a mirror could serve an older index still validly signed, as the Azure mirror could. Apt's timeout bounds a connection, not a name that never resolves, so a lookup stalled as on 2026-11-11 is ended by the step's own three minutes, as before. The mirror is pinned, so a fault of kernel.org's is the Factory's to see and change | Named, as the residual of a dependency outside the repo |
| How it is held | `tests/test_tools.py::test_the_cli_install_reads_only_signed_sources_over_https_by_its_own_list` holds the block to what it may say, not to words it may not: ten lines; three sources each matching, in full, the keyring, HTTPS, the mirror by its name and an Ubuntu suite, all three suites, the first starting the list; two apt lines each with exactly its options. A mutant weakens each | A list of forbidden words let weaker blocks through (the Claude review of the fix) |

## Why

Decision 0106 took bubblewrap from the runner's own mirror because it was the nearest. That mirror's name, and every Ubuntu name, failed to resolve for hours, and the Factory could not review anything. A mirror outside the name that failed, read by a list the block writes itself, takes the image's network choices out of the one step that must fetch.
