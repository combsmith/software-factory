# 0191. A Pause the port could not read is named by which read it was and why

Status: accepted. The Factory Builder's ruling of 2026-11-10, after slice 1's seventh dry run, on pull request 688, "AGENTS.md: say what is built; drop the model claim no check holds", stopped in the approving act at `pause_unreadable`: the first Run to say which read it was (decision 0187), and still not which of the Pause's two reads, or how it failed. It amends 0179's row "The parts", which were the snapshot's alone, and 0187's row "A part not as its schema holds it", for the Pause.

## Decision

| What | Decided | Because |
|---|---|---|
| The parts | The Pause's port says, beside the read it hands back, why each scope it could not read was unreadable, by a code of its own: `org_refused`, GitHub answered the repo's list of the org's variables 403 or 404; `org_unnamed`, that list was read whole and does not name `FACTORY_PAUSED`; `repo_refused`, GitHub answered the repo's own variable 403; `org` and `repo`, anything else of that scope's read. A 403 that is a rate limit's, answered with no request left or a time to wait, is anything else, and no refusal; so is a refusal on the last request left, which the port cannot tell from one. A 404 is never a limit's. `explained` in `adapters/pause.py` gives them, the org's and then each repo's as they are read | The Pause is two reads, and each fails in more than one way. A grant the token lacks, a variable the org does not share with the repo and an answer cut short each ask a different person for a different thing |
| A 404 on the repo's own variable | Stays a variable GitHub holds none of, as the port has read it, and is no refusal | A refusal there is a 403. The port cannot tell a 404 that hides the variable from one that says there is none, and does not guess |
| The code | The approving act asks the read again for the Pause by name. A Pause that is unreadable because the port could not read a scope is then raised as a read of the `pause` stage, its part the first such scope's, and the act records it `pause_<part>_unreadable`, as it records a snapshot's part. It is raised after the run records are found unread, and, as any read raised, before a part is held to its schema | 0187's naming, by `unread` in `harness/shared.py`. The act records every fault of the read again, so the code is the only place the read can be told |
| What stays | `read` hands back what it did, so the Controller, its brake before a dispatch and its health file read the Pause as before, and `pause_unreadable` is still their one code. Apply does not ask by name, and names its Pause in its own order, as it did. A scope that pauses is a Pause whatever else was not read, and nothing is raised. In the approving act `pause_unreadable` is left for a Pause the port read whose value is no Pause, and for a fault of the read's own code. The outcome's kind does not change, so no Decision moves | Only the approving act's reason is finer |

## Why

The seventh dry run spent a Release to learn that the Pause could not be read through the approver's token. The org's variable and the repo's both read `false` to the Controller, so the next question was which of the two reads the token was refused, or whether the list it was given left the variable out. The Run could have said so.
