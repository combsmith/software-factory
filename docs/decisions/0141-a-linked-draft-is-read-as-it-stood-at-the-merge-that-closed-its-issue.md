# 0141. A linked draft is read as it stood at the merge that closed its issue

Status: accepted. Replaces `docs/decisions/0139-a-platform-close-keeps-the-state-a-person-set-on-an-issue-held-or-not-served.md`, and keeps all of it but what it says of a linked draft, which it overturns: that a person's hands-off on a draft, and a Hold on one, are read from the draft's flag as it stands now. The Factory Builder's rulings of 2026-11-04 on "Facts: the times of a link, a left-out label and an issue's type, so that row 1 reads them at the merge" (issue 542), of "Epic: slice 1, first approval. A Release on next reviews a pull request to this repo, and the machine user's approval stands" (issue 182), which split it three ways: this change, "Trial P-61: an issue's type changes and a pull request linked by hand, each timed on the issue's timeline" (issue 551), and "Facts: a closing keyword's link timed by the first pass that saw it, and the Consumer entry at the merge (after the first cut)" (issue 552).

## Decision

| What | Decided | Because |
|---|---|---|
| The fact | Each linked pull request in `issue-facts/1` carries `draft_events`: each conversion to a draft and each marking ready on its timeline, with its time. One opened as a draft has none for it, and the last is its flag now; a flag that disagrees with its last event, or an event that cannot be read, defers, `linked_unreadable` | `trials/P-33.json`: a canary pull request marked ready, converted to a draft and marked ready again has each as its own event, a second or two apart; one left a draft from its opening has none. An unreadable fact never yields an action |
| The flag at a time | A linked pull request was a draft at a time where its flag now, with every event after that second undone, says so, or where it was one at any moment of that second: before its first event it was what that event undid | The reading that stops work wins a tie, as decision 0139 reads a label in the merge's second |
| A draft at the merge | Row 1 reads a linked pull request's draft flag as it stood at the first merge that closed the issue. A person's hands-off on a draft at the merge, placed in its second too, and that no person has removed since, keeps `not_served`, `merged_while_hands_off`, as one on the issue does. A Hold on a draft at the merge, or hands-off no person placed, keeps `held`, `merged_while_held`. A pull request ready at the merge carries neither for the issue, whatever its flag now | These label events, and now the flag, carry their times, so the State at the merge can be read without letting a later change move a `done` issue. Marking a draft ready after the merge, or converting a ready one, changes nothing |
| What carries no time | When a pull request became linked: one opened by the merge is read as linked then, as before. The Consumer entry, whose configuration has no history, a left-out label, whose list is the entry's as it stands now, and the issue's type. Each reads as decision 0139 reads it. So the queue's merge on an issue the entry leaves out, or from two links, may still leave `not_served` or `held` by the platform, and a pull request opened before the merge and linked since may still place its Hold there. Issue 551 asks the trial for a type and a link by hand; issue 552 gives a keyword's link the time of the first pass that saw it, and leaves the entry, as ruled, until a Consumer needs it | GitHub dates a keyword's link at the first mention of the issue, not at the keyword (`trials/P-48.json`), and a link by hand and a type change are untried; a left-out label read at the merge against today's list would bring back what the Factory Builder's ruling (b) on "A platform close keeps the State a person set on an issue held or not served" (issue 522) took out |
| The exploration | The queue merges the Factory's and an admitted outsider's ready pull request also from a person's hands-off on a linked draft, and the exploration records each change of a draft's flag | Each case explored, not assumed |
| What stays | Everything else decision 0139 decides, as it words it, and with it decision 0028 and decision 0132 as 0139 keeps them | Only the lines on a linked draft are overturned |

## Why

Decision 0139 kept the State a person set on an issue where the facts could place it at the merge, and named a linked draft's flag as one they could not. A pull request's timeline gives each change of that flag with its time, so the flag at the merge can be read, and a draft's hands-off and Hold are placed as the issue's are.
