# NNNN. A changed line of Python no test notices is reported for a month before it can fail

Status: accepted. The Factory Builder's rulings of 2026-11-07 on the design note for "A changed line of Python that no test notices fails verify, unless the change says it keeps behaviour" (issue 589). This is its advisory check: a workflow of its own, `untested`, that reads every pull request, fails none, and reports what it finds for a month, from the day it merges.

## Decision

| What | Decided | Because |
|---|---|---|
| What is read | Each hunk of `git diff -U0` from the merge base of the base and the head, in a `*.py` outside `tests/`, `trials/`, `examples/` and `schemas/`, but those of the `ISSUE` and `MUTANTS` lists of `tools/mutants.py` that are its data: a hunk each of whose lines, added and removed, is of an entry made of constants, names and the calls of its helpers, or is blank or a comment, and is no line on which any other part of the list starts or ends. A hunk that touches a comprehension, a condition or any other code there, beside an entry or not, is read. A hunk whose module reads the same to Python with the hunk reverted, its docstrings aside and, where annotations are not evaluated, its annotations, is never run. A path of any character but a word's, `.`, `/` and `-` is counted and never read, nor printed | The merge base keeps main's later changes out. Code in the lists decides which mutants run, so it is behaviour (the security pass on this pull request). A reflowed docstring or a comment changes nothing, and is the commonest false finding. A path is the pull request's text, and the log runs what a line starts with |
| The edit | Every hunk is reverted alone first (ruling 1). An edit that does not parse is UNPARSABLE, one whose module will not import is UNIMPORTABLE, and one that only a test raising SyntaxError, IndentationError, ImportError, ModuleNotFoundError or NameError notices, or that leaves a test module unable to import, is CRASHED. None of those is a kill. Each falls back to its file's every hunk reverted together, then, for a hunk that adds more than 40 lines alone, to at most six mutants of those lines: a condition negated, a comparison off by one, a statement dropped, a constant changed, never of a line that is only a string, a print, a log or a raise. A hunk no edit of which runs is UNCHECKED, with its reason, and one whose every mutant the budget left is UNCHECKED "over budget". A kill of the file's revert may be a neighbouring hunk's, so it is counted apart, `killed_by_file`, never as the hunk's own kill; what it counts for once required is the switch's | Ruling 1: revert first on every hunk, and mutants only as the fallback, on hunks over 40 lines. A crash says a name went, not that a rule did. AttributeError stays a kill, since tests assert on attributes |
| A kill | Through `tools/mutants.py`'s own `attempt`: a failure kills only when the one test that failed fails again alone on the edit and passes alone without it; else it runs once more, and a second failure not the edit's is FLAKY. A run that hangs is an ERROR | The mutant run's rule, whole, so the two cannot drift |
| The tests run first | For a hunk outside `tools/`, each test module that imports its module, or a module that imports it at any remove. For a hunk in `tools/`, each class of such a module that reaches it, directly or through a helper at the top of the module, and of a class `WHOLE_TOO_LONG` names, each of its methods that does; a module that holds such a class is treated so too. `tests/test_simulator.py` and `tests/test_issue_simulator.py` are left to the whole suite, which runs, in the mutant run's parts, when the first tests pass | Ruling 2: name test classes, not whole modules, for `tools/`. `tests.test_tools` whole took 595 s on a desk |
| The budget | 20 minutes from the job's start, after which no run of the tests begins but the run of one test alone that confirms a kill. Edits go smallest file first. An edit the budget leaves is UNCHECKED, "over budget". The step has 33 minutes, since a run begun runs to its end, at most `TIMEOUT`, 10 minutes | The design note's aim, to end inside `checks`. The month measures where the budget binds |
| The trailer | `Behaviour-preserving: <path>:<start>-<end>`, in the head's lines, read from the head commit by git's own parser, covers a survivor, or a hunk UNCHECKED, when it holds every line the hunk adds, or for a hunk that only removes, the line after. A trailer that cannot be read, names a file the change leaves as it was, or names no line any hunk changed, is a problem; every hunk of the change counts, those never run among them, so a trailer on a reworded docstring is none. The log gives each uncovered survivor the exact trailer line it needs | The issue's own form. The head's lines move with each fix round, so the head alone is read |
| Where it runs | `.github/workflows/untested.yml`, one job, `untested`, on `pull_request` and `merge_group`. It checks out the base and runs the base's `tools/untested.py`, which fetches the head and exports it with `git archive`; the head's tests run in copies of that. On a merge group it says it did not run, and exits | Decision 0023: a change cannot set the rules it is read by. The design note said `pull_request` alone; `tools/check_workflows.py` holds every workflow that runs on `pull_request` to run on `merge_group` too, so the tool, not the workflow, declines the merge group. On the pull request that adds the job the base has no tool, so it fails that once, and blocks nothing (Argon's read of that pull request) |
| Advisory | In the month the job is in no job's `needs` and exits 0 whatever it finds or fails to find. It writes each hunk's outcome to the log, a warning on each uncovered survivor's lines, a table of what was not killed to the job's summary, and a last line, `untested/1` and its counts: the hunks, killed and killed only by the file's revert, survived and survived that only remove, unchecked and over budget, flaky, in error, the file and mutant fallbacks each tried, whatever edit gave the outcome, those covered, the trailers and their problems, the seconds, and what was never read and why | A red advisory check would teach people to read red as noise. The counts are what the weekly list is made from |
| The month | It starts the day this merges. This lane owns it, and posts a list to the issue each week, counting how often the fallback ran and how often a hunk came out UNCHECKED (ruling 2) | So the 40-line limit, the budget, and whether a hunk that only removes or a mutant may ever fail, are judged on numbers |
| The switch | Stays open until the month ends (ruling 3). Two routes stand: A, adding `untested` to `verify`'s `needs` in `.github/workflows/verify.yml`, a protected path, the Maintainer's approval; B, a second required context in the `main` ruleset, the Maintainer's alone. A puts the check in the path of the Maintainer's emergency fix (design §9.1, "One rule protects recovery"). The choice, with the month's numbers, is the Maintainer's | Ruling 3 withdrew the note's recommendation of A |
| What the head's code can do | The head's tests run in the same job as the base's tool, as they run in `checks` and in each `mutants` leg, with no token, `contents: read`. The tool takes the files the runner reads back out of the environment before any of the head's code runs. A test could still reach the job's summary, its log or the base's checkout by other means, and print a forged `untested/1` line, so the weekly list is read from what the head's code could write | In the month nothing rests on the job. Before the switch, the verdict must leave the head's process tree, its tests run in a job or a container of their own and only their outcomes coming back: that is the switch's to decide, with its route |

## Why

A changed line that no test notices is behaviour nothing holds. The mutant run holds the rules someone wrote a mutant for; this asks of every changed line. Made required at once, its false findings, a refactor, a performance change, a guard for a failure no test can provoke, would stop work before anyone knew how often they come. A month of reports first sizes the cost and the noise.

## Boundaries

| Boundary | Check |
|---|---|
| A hunk is reverted alone, and its outcome is the mutant run's `attempt`: killed when a test notices, SURVIVED when none does | `tests/test_untested.py::test_a_revert_no_test_notices_survives_and_one_a_test_notices_is_killed`, `tools/untested.py`; mutant: "a hunk Python reads the same is run" |
| A hunk Python reads the same, a docstring, a comment or an annotation not evaluated, is never run | `tests/test_untested.py::test_a_hunk_that_changes_nothing_python_sees_is_never_run`, `tools/untested.py`; mutant: "a docstring is read as behaviour"; mutant: "an annotation is read as behaviour"; mutant: "an annotation Python evaluates is dropped" |
| A crash is never a kill: an edit a crash alone notices falls back to its file's revert, whose kill is counted apart | `tests/test_untested.py::test_an_edit_a_crash_alone_notices_falls_back_to_its_files_revert`, `tools/untested.py`; mutant: "a revert a crash alone notices is a kill"; mutant: "an edit that cannot run never falls back to its file"; mutant: "a kill of the file's revert is counted as the hunk's own" |
| An edit that does not parse, or whose module will not import, is never run, and each fallback tried is counted | `tests/test_untested.py::test_an_edit_that_does_not_parse_or_import_is_never_a_kill`, `tools/untested.py`; mutant: "an edit that does not parse is run"; mutant: "an edit whose module will not import is run"; mutant: "a fallback is counted only when it gave the outcome" |
| A hunk that only removes is put back where it was, and its survivor is warned of at the line after | `tests/test_untested.py::test_a_hunk_that_only_removes_is_put_back_where_it_was`, `tools/untested.py`; mutant: "a hunk that only removes is put back a line early"; mutant: "a survivor that only removes is warned of a line early" |
| A hunk no edit of which runs is UNCHECKED, only one that adds more than 40 lines falls back to mutants, and nothing in `tests/` is read | `tests/test_untested.py::test_a_small_hunk_no_edit_of_which_runs_is_unchecked_and_a_large_one_gets_mutants`, `tools/untested.py`; mutant: "a test module that will not import is an error, not a crash"; mutant: "a small hunk falls back to mutants"; mutant: "a large hunk never falls back to mutants"; mutant: "a hunk in tests/ is read" |
| At 40 added lines a hunk is UNCHECKED and at 41 it falls back to mutants; one whose every mutant the budget left is over budget | `tests/test_untested.py::test_a_hunk_of_more_than_forty_added_lines_alone_falls_back_to_mutants`, `tools/untested.py`; mutant: "a hunk of forty added lines falls back to mutants"; mutant: "a large hunk whose every mutant ran out of budget is not over budget" |
| A mutant is made of an added line, never of a quiet one, and at most six of a hunk | `tests/test_untested.py::test_a_mutant_is_made_of_an_added_line_and_never_of_a_quiet_one`, `tools/untested.py`; mutant: "a hunk's mutants are not capped"; mutant: "a quiet line is mutated" |
| No run of the tests begins past the budget, and an edit it leaves is UNCHECKED | `tests/test_untested.py::test_no_run_of_the_tests_begins_past_the_budget`, `tools/untested.py`; mutant: "a run of the tests begins past the budget" |
| A path a pull request names is read only in plain characters | `tests/test_untested.py::test_a_path_a_pull_request_names_is_read_only_in_plain_characters`, `tools/untested.py`; mutant: "a path a pull request names is read whatever its characters" |
| The entries of the mutant lists are data, and the code among them and the runner below them are read | `tests/test_untested.py::test_the_lists_of_mutants_are_data_and_the_runner_below_them_is_read`, `tools/untested.py`; mutant: "a hunk that touches a line of code in the mutant lists is read as data"; mutant: "an entry of the mutant lists that decides is data"; mutant: "a line of code beside an entry of the mutant lists is data" |
| For a hunk in `tools/`, the classes that reach it run first, and of a slow class its methods | `tests/test_untested.py::test_a_hunk_in_tools_names_the_classes_that_reach_it_and_a_slow_class_its_methods`, `tools/untested.py`; mutant: "a hunk in tools/ names its test module whole"; mutant: "a slow class is named whole" |
| Elsewhere, each module that reaches the hunk at any remove runs first, but the slow ones | `tests/test_untested.py::test_a_hunk_elsewhere_names_each_module_that_reaches_it_but_the_slow_ones`, `tools/untested.py`; mutant: "a slow module is run first"; mutant: "a module that reaches the change through another is not run first" |
| A trailer covers a hunk only when it holds every line the hunk changed | `tests/test_untested.py::test_a_trailer_covers_a_hunk_only_when_it_holds_every_line_the_hunk_changed`, `tests/test_untested.py::test_the_head_commits_trailer_covers_its_survivor`, `tools/untested.py`; mutant: "a trailer covers a hunk it holds part of"; mutant: "a trailer is held to the hunks run alone" |
| A trailer that names no changed line, a file the change leaves, or that cannot be read, is a problem | `tests/test_untested.py::test_a_trailer_that_names_no_changed_line_or_cannot_be_read_is_a_problem`, `tools/untested.py`; mutant: "a trailer that names no changed line stands"; mutant: "a trailer that names a file the change leaves stands" |
| The head's tests are given none of the files the runner reads back | `tests/test_untested.py::test_the_heads_tests_are_given_no_file_the_runner_reads_back`, `tools/untested.py`; mutant: "the head's tests are given the files the runner reads back" |
| In the month it reads no merge group, and the job is green whatever fails | `tests/test_untested.py::test_on_a_merge_group_it_does_not_run_and_it_is_green_whatever_fails`, `tools/untested.py`; mutant: "a merge group is read in the month"; mutant: "what fails the check turns the job red" |
| An uncovered survivor is warned of on its lines and told its trailer, and the counts close the log | `tests/test_untested.py::test_a_survivor_is_warned_of_on_its_lines_and_told_its_trailer`, `tools/untested.py`; mutant: "a survivor is not warned of" |
| The job runs the base's tool, and no job needs it | `tests/test_untested.py::test_the_job_runs_the_bases_tool_on_both_events_and_no_job_needs_it`, `.github/workflows/untested.yml`, `.github/workflows/verify.yml`; mutant: "the advisory job checks out the head"; mutant: "verify needs the advisory job" |
