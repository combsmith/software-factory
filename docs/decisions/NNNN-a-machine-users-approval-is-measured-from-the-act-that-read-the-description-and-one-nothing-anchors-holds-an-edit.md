# NNNN. A machine user's approval is measured from the act that read the description, and one nothing anchors holds an edit

Status: accepted. The Factory Builder's ruling of 2026-11-07 on issue 195, "The approving act: the machine user approves from a Run with no Engine, bound to the admitted commit", answering the requirement issue 550, "Gaps record 0140 names: edits around the approval and the queue's merge, issues linked by hand", left on it. It amends decision 0135's anchor and the first clause of decision 0140's row "What it does not see". Nothing else in either changes.

## Decision

| What | Decided | Because |
|---|---|---|
| An act's approval | A machine user's approval is measured from when the latest `issue-approval` Run on its content made at or before it was made: its dispatch, which a re-run keeps, or its start where that is earlier or no dispatch is read. It is read from this item's run records | The approving act reads the description after its Run is made and before its approval lands. Measured from the approval, an edit in those seconds came before it and held nothing. A Run's start is its latest attempt's, so a re-run after the approval would have moved it past the read |
| A browser's approval | One with no such Run, where a record of this item began at or before it, is measured from its own time | Decision 0046 lets the Maintainer approve his own change as the machine user in the browser, and a person reads as they approve. Holding it would hold nearly every such pull request, since a reviewer App edits most descriptions once, seconds after opening (decision 0140) |
| One nothing anchors | One with no record of this item that started no later than it, with an act on its content started after it whose dispatch was not read, which may be a re-run of the act that read, or with a record whose dispatch and start both cannot be read, is measured from before every time, so any edit holds the item (`description_edited_after_approval`) until a person approves after the edit, as before | Records expire oldest first, and an act's Run is made before its approval: it is not gone while a record made before it stays. A record reaches back by its start, which a re-run only moves later. With none, it may be an act's whose Run is past retention, and falling back to the approval's own time would open the gap again. A record list that cannot be read already defers the item as incomplete facts |
| The residuals | An item whose oldest retained record postdates a browser's approval holds on any edit, and needs a person to look; that fails safe. Three pass an edit unseen once the act's Run is gone: an act's Run a person deletes by hand while an older record stays; a Run made while the act ran, which waits in the item's lane (section 2.4, rule 4) but whose record's start is when it was made (`trials/P-44.json`), once the act's Run is past retention and it is not; and a record whose start is no time beside a dispatch that is one. A follow-on issue closes the last two | The first is only on an item older than the records' retention. The others need a person to delete a record, the retention's edge to fall in the act's own seconds on an item older than it, or a record no port of this repo writes |
| A record in the approval's second | It reaches back, as one before it does, both as an act's Run and as a record older than a browser's approval | An act's Run is made seconds before its approval, and the simulator's world records its act's Run in its approval's own second. Any other Run made in that second follows the act's end, which reads back and uploads after its approval |
| What it reads | The run records the Kernel already has, and their `dispatched_at` and `started_at`. `facts/1` gains no field, so the held-out cases are unchanged | A record already says when each Run was made |
| The simulator | `description_anchor` takes the records by name only. Its default, no records, measures each approval from its own time, which is the anchoring this record rules out, so it exists only for the simulator's world, whose act's Run starts in its approval's own second. `derive` always gives the records, an empty list included, and a test holds that nothing else calls it. `sim/world.py` and `tests/test_simulator.py`, both protected, are unchanged; teaching the world's model the Run anchor is a protected edit for the Maintainer, filed as its own issue | The world's approvals all come from its act, so its runs read alike either way |
| What stays | Decision 0135's rule, the first approval since a person's look and never the latest, the outsider's anchor, and its handling of a second. Decision 0140's other clauses: an edit after the last pass and before the queue's merge, and an issue linked by hand | Only the anchor's time changes |

## Why

Decision 0140 named it: an edit after the approving act's last read and before its approval lands is timed before the approval, and holds nothing. The act re-reads the item and asks the Kernel again before it approves (decision 0055), so the only edit it cannot see is one in its own last seconds. When its Run was made is earlier than that read, so measuring from it errs early, and needs no new fact.
