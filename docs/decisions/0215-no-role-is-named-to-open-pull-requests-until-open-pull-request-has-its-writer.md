# 0215. No Role is named to open pull requests until open_pull_request has its writer

Status: accepted. The ruling of 2026-11-13 on box 13 of "Epic: slice 1, first approval. A Release on next reviews a pull request to this repo, and the machine user's approval stands" (issue 182), by the Solution Architect, delegated, with the Factory Builder, on the Maintainer's approval while away; built for "A check refuses naming a Role to open pull requests while open_pull_request has no writer" (issue 808), which restates the limit of "Acceptance: a pull request is bound to the issue it serves by its Run or branch, not by its author's closing link" (issue 295), its design ruled by the Factory Builder on 2026-11-13. It amends decision 0068's row "The Run record" and decision 0047's row "The known limit".

## Decision

| What | Decided | Because |
|---|---|---|
| The limit, restated | The gap a pull request's author's closing link leaves, which "Acceptance: a pull request is bound to the issue it serves by its Run or branch, not by its author's closing link" (issue 295) said must not outlive slice 1, must not outlive the moment any Role is named to open pull requests, or any contract is in force | The binding by the opening Run's record and by its branch is built and tested; its writer, "Acceptance: a pull request the Factory opens is bound to its issue by the Run that opened it" (issue 342), waits on the push Effect, which is slice 2's. Nothing the binding guards exists yet: no Role opens a pull request, and no contract is in force |
| The check | `tools/check_authority.py` refuses a configuration that names a Role for `open-pull-request` in `issues.intents` while `open_pull_request` has no writer, and names the first part of the writer missing. With the Role null, as `config/defaults.json` has it, it passes. `tools/check_examples.py` holds a configuration's counter-example to it | A limit that is only remembered is not held |
| The writer | Three marks, each read from the code's syntax, never by importing it: an adapter function under `adapters/` that builds a request whose method is a write and whose path, written as text, is a repo's pulls and nothing after it; a step of the Harness that `tools/check_writes.py`'s CALLERS lists as reaching that function; and, in that step's module, a call of `harness/apply.py`'s `opened`, which records the Run that opened the pull request (decision 0097) | The writer the row above waits on is the change that makes all three true. A read of the pulls, a write to one pull request, a caller outside the Harness, and a step that records nothing do not. A method or a path that is not text is not read as an opening, so it never turns the check green |
| What remains | Nothing checks that no contract is in force: the check holds the Role half of the restated limit alone. The marks are syntax: a step could call `opened` and reach the opening adapter without opening a pull request in the same flow. CALLERS is held true by `tools/check_writes.py`, never by this check | Named, for the change that brings in the first contract |

## Why

Naming an opening Role in `config/defaults.json` is a one-line change, and the Kernel would then bind that Role's pull requests by their branch and their opening Run's record, while no Run ever records one. A check makes the configuration and the writer land together.

## Boundaries

| Boundary | Check |
|---|---|
| A Role named for `open-pull-request` is refused until an adapter opens a pull request, a step of the Harness reaches it as CALLERS lists, and that step calls `opened`, each missing part named in turn; a read of the pulls, a write to one pull request, a method or a path not written as text, a caller outside the Harness, a step reaching another writer, and a step calling no `opened` or another module's do not count; `opened` imported by its name, under another, or with `harness.apply` whole, does; none named passes; the counter-example is refused | `tests/test_tools.py::test_a_role_named_to_open_pull_requests_waits_on_its_writer`, `tools/check_authority.py`, `tools/check_examples.py`, mutant: "a Role named to open pull requests is never refused", mutant: "an opening Role named none is refused", mutant: "a read of a repo's pulls opens one", mutant: "a method not written as text may open one", mutant: "a write to one pull request opens one", mutant: "any request opens a pull request", mutant: "a caller outside the Harness reaches the opening", mutant: "a step reaching any writer reaches the opening", mutant: "a step need not record the opening", mutant: "any module's opened records the opening", mutant: "any call of a step's records the opening", mutant: "opened imported under another name records nothing", mutant: "harness.apply imported under another name records nothing", mutant: "the configuration is not held to the opening", mutant: "a counter-example configuration is not held to the opening", `examples/invalid/config.an-opening-role-with-no-writer.json` |
