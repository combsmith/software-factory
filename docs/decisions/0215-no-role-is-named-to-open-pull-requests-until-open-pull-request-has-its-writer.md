# 0215. No Role is named to open pull requests until open_pull_request has its writer

Status: accepted. The ruling of 2026-11-13 on box 13 of "Epic: slice 1, first approval. A Release on next reviews a pull request to this repo, and the machine user's approval stands" (issue 182), by the Solution Architect, delegated, with the Factory Builder, on the Maintainer's approval while away; built for "A check refuses naming a Role to open pull requests while open_pull_request has no writer" (issue 808), which restates the limit of "Acceptance: a pull request is bound to the issue it serves by its Run or branch, not by its author's closing link" (issue 295), its design ruled by the Factory Builder on 2026-11-13. It amends decision 0068's row "The Run record" and decision 0047's row "The known limit".

## Decision

| What | Decided | Because |
|---|---|---|
| The limit, restated | The gap a pull request's author's closing link leaves, which "Acceptance: a pull request is bound to the issue it serves by its Run or branch, not by its author's closing link" (issue 295) said must not outlive slice 1, must not outlive the moment any Role is named to open pull requests, or any contract is in force | The binding by the opening Run's record and by its branch is built and tested; its writer, "Acceptance: a pull request the Factory opens is bound to its issue by the Run that opened it" (issue 342), waits on the push Effect, which is slice 2's. | The writer | Three marks, each read from the code's syntax, never by importing it: an adapter function under `adapters/` that builds a request whose method is `POST`, the one write that creates, and whose path is a repo's pulls and nothing after it, each read as text: a literal, one formatted with `%`, an f-string, or a name bound once to one of those in the function or at its module's top, given by place or by keyword; a step of the Harness that `tools/check_writes.py`'s CALLERS lists as reaching that function; and, in that step's module, a call of `harness/apply.py`'s `opened`, imported absolutely or relatively, or spelt out where `import harness.apply` binds it, which records the Run that opened the pull request (decision 0097) | The writer the row above waits on is the change that makes all three true. A method or a path that cannot be read as text is not read as an opening, so it never turns the check green; a writer written that way stays red, and the refusal says which mark it lacks |
| What remains | Nothing checks that no contract is in force: the check holds the Role half of the restated limit alone. The marks are syntax: a step could call `opened` and reach the opening adapter without opening a pull request in the same flow. CALLERS is held true by `tools/check_writes.py`, never by this check | Named, for the change that brings in the first contract |

## Why

Naming an opening Role in `config/defaults.json` is a one-line change, and the Kernel would then bind that Role's pull requests by their branch and their opening Run's record, while no Run ever records one. A check makes the configuration and the writer land together.
